# 远程服务器部署详细流程

> 本文仅为规划。本轮没有部署项目。

## 1. 变更窗口与备份

1. 确认 Java、Node、Python、MySQL、iServer/iPortal、Nginx 版本和许可证。
2. 记录现有进程、端口、服务 URL、匿名权限和健康状态。
3. 备份数据库、Nginx 配置、iServer 工作空间、iPortal 资源目录、UDBX、SCP/S3M 缓存。
4. 记录当前前后端版本和可回滚制品校验和。
5. 不把密码、JWT、算法密钥或和风密钥写入仓库、命令历史和日志。

## 2. 密钥与环境

由服务器密钥管理或受限环境文件注入：

- `JWT_SECRET`（至少 32 字符）
- `DB_USERNAME`、`DB_PASSWORD`
- `ALGORITHM_API_KEY`
- `QWEATHER_API_KEY`、`QWEATHER_LOCATION`
- `CORS_ALLOWED_ORIGINS`
- 前端只注入公开 URL，不注入后端私钥

环境文件权限限制为运行账户可读。

## 3. 数据库迁移

1. 在只读备份完成后进入维护窗口。
2. 先在恢复副本运行 `db/migrations/006_add_realtime_sensor_reading.sql`。
3. 校验历史行数不变、`event_id` 无空值且唯一索引存在。
4. 正式库执行同一迁移。
5. 回滚时先停写，备份新增数据；移除唯一索引和新列前确认消费方已退回旧版本。

## 4. 六个 EPSG:4490 三维服务

对加工厂房、生产厂房、原材料仓库、换热器、立式罐、蒸馏塔逐个执行：

1. iDesktopX 打开源模型/缓存副本，禁止覆盖原 SCP/S3M。
2. 目标坐标系设置为 `China 2000 / EPSG:4490`。
3. 用主场景控制点做平移、旋转、高程配准，检查与 `huangong_4490` 重合。
4. 写入稳定对象 ID、模型名称和设施 ID。
5. 生成独立 S3M 缓存；检查 config 的 CRS、position、geoBounds 和 heightRange。
6. 发布独立 Realspace 服务，服务名与 `spatial-assets.4490.json` 对齐。
7. 浏览器依次验证 config 200、首层瓦片 200、模型可见、近景相机正确。
8. 任一服务失败只下线该服务，不改变主场景。

## 5. 二维 UDBX 服务

1. 复制现有 UDBX，原文件只读保留。
2. 生成 EPSG:4490 展示副本和 EPSG:4547 分析副本。
3. 发布两个独立地图/数据服务。
4. 为展示地图建立多级缓存或矢量瓦片，配置 256/512 高 DPI 瓦片、合理比例尺和完整范围。
5. 验证文字、建筑边界、缩放和平移；禁止再用单张 `image.png` 作为可缩放主底图。
6. 空间分析端点只接受适配器转换后的 4547，UI 坐标始终返回 4490。

## 6. iPortal/iServer 恢复

先只读检查：

- 进程和端口是否存活但线程阻塞
- iServer/iPortal 日志中的许可、数据库、磁盘、内存和资源加载错误
- iPortal 数据库连接池
- 大屏资源是否存在、匿名访问权限、引用 URL
- 反向代理 Host、X-Forwarded-*、WebSocket、超时
- iframe 的 CSP/X-Frame-Options；优先新标签打开

只重启现有故障服务，不在排障阶段部署本项目。恢复后验证匿名窗口可打开指定大屏，再允许前端健康检查显示在线入口。

## 7. 应用构建

后端：

```powershell
cd backend
mvn clean test
mvn -DskipTests package
```

前端：

```powershell
cd frontend
npm ci
npm run validate:spatial-assets
npm run test:unit
npm run typecheck
npm run lint
$env:NODE_OPTIONS='--max-old-space-size=12288'
npm run build
```

Python（依赖锁和测试依赖确认后）：

```powershell
uv sync --extra test
uv run ruff check algorithm
uv run pytest algorithm/tests
```

## 8. Nginx

- `/` 指向前端静态目录，Hash 路由无需额外回退规则。
- `/api/` 反代 Java 8081，配置请求 ID、合理超时和 SSE：
  - `proxy_buffering off`
  - `proxy_cache off`
  - `proxy_read_timeout 1800s`
- `/algorithm/` 反代算法服务，密钥只在服务间传递。
- `/iserver/` 代理本地主园区 iServer，`/remote-iserver/` 去掉此前缀后代理六个独立场景所在的远端 iServer，`/iportal/` 代理远端 iPortal；三者保留必要转发头。
- `/remote-iserver/` 必须支持 Realspace config 派生的 S3M/纹理/属性相对请求，并设置不低于 120 秒的读取超时；缺少该 location 时开发环境可用但生产构建会固定返回 404。
- 限制传感器批量请求体大小和速率；SSE 连接单独限流。

## 9. 上线顺序与健康检查

1. 数据库迁移。
2. iServer 主场景、六个附属场景、二维服务。
3. Java 后端，检查 `/healthz`。
4. 算法服务，检查 health 和三传感器粒子滤波样例。
5. 前端静态资源。
6. iPortal 链接最后开放。

验收：

- `/screen`、`/smart-map`、主页、监控页均可打开。
- 传感器接入、幂等、SSE 续传。
- 七场景 config/瓦片、逐场景近景和失败保护。
- 出入口不漂移。
- 风向与扩散方向一致，KDE 位于真实模型位置。
- 二维缩放清晰，坐标往返误差在验收阈值内。
- 控制台无新增 page error，网络无非预期 4xx/5xx，长时运行内存稳定。

## 10. 回滚

1. 关闭新增功能开关，优先恢复 `/screen` 和主场景。
2. Nginx 切回旧静态目录和旧后端 upstream。
3. 停止新后端/算法进程，启动已校验旧制品。
4. 六个附属服务逐个下线，不影响主服务。
5. 数据库优先保持向后兼容；只有旧版本确实不兼容时才在停写和备份后回滚结构。
6. 记录故障时间、请求 ID、日志、回滚版本和恢复时间。
