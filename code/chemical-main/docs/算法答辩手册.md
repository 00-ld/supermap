> 配套：`docs/溯源算法讲解.md`（360 行完整讲稿，必读）、`docs/flowcharts/`（4 张图）、`docs/algorithm-implementation-verification-supermap-principle.md`

## 一、AI 提问应对（先想清楚，再上场）

### 1.1 评委问 AI 的三个真实意图

评委（大多是行业专家/高校老师）问"这是不是 AI 做的"，**不是在审查你，而是在试探三件事**：

| 意图 | 潜台词 | 破法 |
|---|---|---|
| 考察真实性 | "你是不是拿 AI 生成个东西就来参赛？" | 展示你做的**决策和验证**，不是展示代码量 |
| 考察理解深度 | "代码你能讲得明白吗？" | 讲**设计思想**，讲"为什么这么选" |
| 考察工程素养 | "你知道 AI 的边界在哪吗？" | 讲**你否掉了什么**（弃用 U-Net、弃用合成观测冒充真数据） |

**结论：评委真正想听的不是"代码谁写的"，而是"设计谁定的、怎么验证的"。而这两件事，恰恰全是人做的——你有大量证据。**

### 1.2 回答框架：承认工具 + 立即转入技术深度

> **直接问"算法是不是 AI 写的？"时的三段式回答（背下来，10 秒内说完）：**

```
"代码的编写借助了 AI 辅助工具，这跟现在行业里用 GitHub Copilot 是一样的。
 但算法本身不是我让 AI 拍脑袋写的——选型、物理建模、参数标定、验收阈值
 都是我定的，AI 只是把设计变成代码。我举三个例子：
 ① 深度学习只占 3% 的残差校正，97% 是物理模型，且遇到没见过的气象特征自动退回纯物理；
 ② 粒子滤波我加了退火和 MCMC 复兴，教科书实现没有；
 ③ 合成观测我明确禁止当真实事故讲，真实数据只用于验证横风向扩散宽度。
 —— 这些决策都是我在把关。"
```

**为什么要这样答而不是否认？**
1. 你的 git 记录、`.codex-runlogs`、对话记录都在仓库里，答辩现场演示时很容易被看到，否认风险极大；
2. 评委自己就用 AI，撒谎会直接摧毁信任——而"诚实 + 深度"的组合在答辩里是加分项；
3. 超图杯考的是**产品链完整度和技术应用**（SuperMap 主链路 + 算法闭环 + 验收证据），不是"手写代码大赛"。

### 1.3 三条底线

1. **不撒谎**。承认 AI 辅助编码，就像承认用了 IDE 一样自然。被追问"哪些是你写的"，就指 `.bat` 部署脚本、坐标系口径文档、验收脚本——这些真是你主导的。
2. **不甩锅**。不说"AI 生成的，我不懂"——这句话等于承认你对作品零贡献。
3. **不慌**。把 AI 问题当"展示理解深度的机会"来答，语气是"正好，我给你讲讲这个算法为什么这么设计"。

### 1.4 如果评委追问细节（比如"粒子数为什么是 12000"）

回答模式：**先说结论 → 给依据 → 给证据位置**。例如：

> "12000 粒子是预算-精度折中。Q 对浓度是线性的，可以向量化批量预测，12000 个粒子在 CPU 上一次前向传播毫秒级。验证脚本用 9000 粒子 × 24 轮、多随机种子做过重复性检查，保证不是靠低预算掩盖不稳定。代码在 `inversion/particle_filter.py:478`，验证在 `validate_particle_filter.py`。"

记住：**每个数字后面都跟着一个"为什么"，这就是"懂"和"不懂"的区别。**

## 二、三大算法讲解卡（背诵版）

> 答辩主链路就三条：**扩散（算浓度场）→ 溯源（倒推泄漏源）→ 疏散（算逃生路线）**。
> 每张卡 = 30 秒电梯版 + 3 分钟标准版要点 + 亮点 + 追问预案。
> 完整细节看 `docs/溯源算法讲解.md`（溯源）+ 各算法 README。

### 卡 1：气体扩散（`algorithm/diffusion/`，主入口 `phase1_diffusion.py`）

**30 秒版：**

> "扩散模块算的是'气体从泄漏点出来，在风里怎么飘、怎么散'。用的是高斯烟羽模型做解析底子，再叠加三维体网格：建筑会挡风（硬遮挡）、道路会形成通风通道（烟囱效应），浓度按风向风速逐帧推进，最后输出整个园区的浓度场，作为预警和疏散的输入。"

**3 分钟版要点（讲"两层结构"）：**

1. **解析底子（`gaussian_plume.py`）**：经典高斯烟羽公式，Pasquill 稳定度分级 A-F，风速按幂律廓线从 10 米外推到释放高度。这是 0 号可信基线——公式来自教科书，可复现可校验。
2. **三维条件化（`phase1_diffusion.py`）**：在解析底子上加园区条件：
   - 建筑 = 硬遮挡体（`build_hard_block_volume`），气体绕不过去；
   - 道路 = 通风通道（`build_channel_segments`），气体沿道路汇流加速；
   - 速度场（`build_velocity_field`）把风、障碍、通道统一成一个三维风场。
3. **物理教师模型（`conditioned_advection.py`）**：确定性的网格化平流-扩散模型，是溯源模块前向模型的"物理锚点"，**不依赖黑箱**。

**亮点（背下来）：**
- 静风限幅 `MIN_WIND_SPEED = 0.3 m/s`：避免静风时浓度奇异——这是工程实践细节，监管实践里也这么限幅；
- 稳定度分级的 WIND_PROFILE_EXPONENT（Irwin 1979 幂律）——引用文献，评委最爱听；
- 真实数据验证：用 Prairie Grass 实测扩散宽度 Sy 验证横风向扩散（`test_real_prairie_grass.py`）。

**追问预案：**
- Q：高斯烟羽的局限？→ "稳态、均匀地形假设，所以我在它之上加了建筑遮挡和通道修正；CFD 太慢做不了实时，高斯+修正是在'够快'和'够准'之间的工程折中。"（`cfd_calibrator.py` 就是干这个标定的）
- Q：为什么不直接用 CFD？→ "实时性。应急场景要秒级响应，CFD 分钟级起步。我用 CFD 做离线标定，在线跑高斯+修正。"（讲"分层精度"是答辩里最显水平的回答）

### 卡 2：气体溯源（`algorithm/inversion/`，主入口 `particle_filter.py`）

**30 秒版：**

> "溯源就是解反问题：只有传感器读数，倒推泄漏源在哪、排多猛。做法是撒 12000 个候选源粒子，让前向模型算每个'如果是你，传感器该读多少'，跟实测比对，像的留、不像的淘汰，迭代收敛后粒子聚成的'概率山'就是源的位置，还附带 95% 可信半径——我不只给一个点，我给出把握程度。"

**3 分钟版要点（讲"四件事"）：**

1. **前向模型 G(θ)（`forward_model.py`）**：给定候选源 (x, y, Q) 预测各传感器浓度。核心设计：**深度学习代理 + 物理锚点**——PyTorch MLP 只做 3% 残差校正（`NEURAL_BLEND_WEIGHT = 0.03`），97% 是物理模型，遇到神经网络没见过的气象特征自动退回纯物理。**这不是黑箱。**
2. **Q 线性 → 解析拟合**：浓度对排放速率 Q 线性，`predict(x,y,Q) = predict_unit(x,y) × Q`。所以位置定了之后 Q 不用搜，最小二乘闭式解 `Q = (g·c)/(g·g)`。这也是 12000 粒子能在 CPU 跑得动的关键（向量化批量预测）。
3. **粒子滤波五步迭代（`particle_filter.py:101`）**：算似然 → 退火（β 从 0 平滑升到 1，防早熟）→ 系统重采样（ESS < 0.55×12000 时触发，淘汰像的复制）→ **MCMC 复兴**（Metropolis-Hastings 加抖动，防退化——教科书实现没有这步）→ 收敛诊断（split-R̂）。
4. **两条物理约束（`_arrival_time_log_likelihood`）**：到达时间差（各传感器首次检测时间两两相减，消掉"泄漏开始时间"这个未知量）+ 上风向信号约束（源不该让上风向传感器有读数）。弱风/少传感器下还能定位。

**亮点（背下来）：**
- "物理为主、神经为辅、按特征兼容性自动切换"——工程严谨性的招牌；
- 到达时间**差**而不是到达时间绝对值——去参量化技巧，评委眼前一亮；
- 输出三层：点估计 + 95% 可信半径 + KDE 概率山 GeoJSON（前端渲染成三维"概率山"）——**反问题诚实表达不确定性**；
- 对照方法 EKI（集合卡尔曼反演）：64 成员集合、卡尔曼式更新，用于"已知候选区再精修"；粒子滤波做全局搜索。两条路线共用前向模型，物理自洽。

**追问预案：**
- Q：为什么不用梯度优化？→ "前向模型含神经网络和上风向硬截断，梯度不光滑；粒子滤波和 EKI 都不需要求导，还天然给出不确定性。梯度法给不出'可信半径'。"
- Q：12000 够吗？怎么保证可重复？→ "默认种子 20250613 全程确定性；9000 粒子 × 24 轮多种子重复性验证（`validate_particle_filter.py`）。"
- Q：15 米命中判据？→ "验收阈值，配合 Prairie Grass 真实扩散宽度 + 合成观测验证。合成观测绝不冒充真实事故数据。"
- Q：AI 的"深度学习"在这算什么？→ "**正好回答你前面的问题**——它只做 3% 残差，是加速器不是决策者，决策是物理模型做的。"

### 卡 3：疏散规划（`algorithm/planning/`，主入口 `dstar_lite.py`）

**30 秒版：**

> "疏散模块算逃生路线。园区道路建成图，扩散模块实时算出的浓度场映射成'危险遮罩'——浓度高的路段走不了。然后用 D* Lite 增量式寻路：泄漏点变了、浓度场变了，不需要从头算，只更新受影响的路段，秒级给出每人/每栋楼的安全出口路线。"

**3 分钟版要点（讲"三个工程点"）：**

1. **路网建模（`build_road_graph`）**：园区道路要素建成带权图，出入口是目标节点。
2. **危险遮罩（`build_danger_mask`）**：扩散浓度场 + 气体特性 → 每条边/每个节点的通行代价（`get_traversal_cost`）。浓度高的代价暴涨 = 这条路被"遮罩"。
3. **D* Lite 增量搜索（`Planner` / `run_dstar_lite_search`）**：为什么选 D* Lite 而不是 A*？→ 应急场景**环境动态变化**（泄漏源移动、浓度场逐帧更新）。A* 每次变化全图重算；D* Lite 只重算受影响部分（`update_planner_for_start_change` / `apply_danger_mask_updates`），秒级响应。这也是名字里"Lite"的含义——轻量增量。

**亮点（背下来）：**
- "A* 是'地图不变算一次'，D* Lite 是'世界一直在变，我跟着变'——应急场景选 D* Lite 是算法选型的正确决策"；
- 危险遮罩把扩散和疏散两个模块**解耦**：扩散只出浓度场，疏散只吃遮罩，模块间单一数据流（这也是给 SuperMap 二维网络分析的对比点：SuperMap 做静态网络分析，动态危险遮罩 + 增量重算是自研的差异化）；
- 批量规划按建筑聚合（`plan_evacuation_routes_by_building`），一栋楼一条主线，不是每人乱跑。

**追问预案：**
- Q：D* Lite 和 A* 区别？→ 上面那句"地图不变 vs 世界在变"，再补一句"D* Lite 用 rhs 值和优先级队列维护增量，代价是第一次搜索稍慢，收益是后续更新快一个量级"。
- Q：和 SuperMap 网络分析什么关系？→ "SuperMap 提供静态路网和空间分析能力做底座（评委要看 SuperMap 产品链），动态危险遮罩 + 增量重算是我们的差异化增强——二维计算引擎 + 三维投影仪的分工口径。"

## 四、一句话总纲（答辩前最后默念）

> **代码是 AI 敲的，算法是人定的，验证是证据说话的。**
> 你答辩讲的是"人定的那部分"——选型、物理建模、参数、验收，这些证据链全在仓库里。
> 溯源讲"概率山和 97% 物理"，扩散讲"分层精度和静风限幅"，疏散讲"世界在变所以选 D* Lite"。
> 这三句话讲清楚，评委不会再有 AI 问题。
