## 一、干了什么

### 1. 模型审核（用户要求的第一优先级）

审核了现有扩散模型（`algorithm/diffusion/phase1_diffusion.py`）是否适用于三维流场：

**结论：不直接适用，需增量改造。**

| 维度 | 官方流场需求 | 现有模型 | 差距 |
|---|---|---|---|
| 场数据 | 每格点 U/V/W 速度向量 | 只有浓度标量 + 常数风向量 | 核心差距 |
| 障碍/通道扰动 | 速度随建筑/道路变化 | 掩码矩阵已预计算（仅用于浓度） | 可直接复用 |
| 垂直分量 | W 分量 | buoyancyMetersPerSecond 仅体元参数 | 需合成 |
| 时序 | 多时序快照 | frames[] 天然时序 | 形状兼容 |

关键复用点：`evaluate_obstacle_effects`（obstacleFactor）、`evaluate_channel_effects`（channelFactor）、
`build_wake_obstacles`（turnBias）——这些已预计算的掩码矩阵被直接复用到速度场合成。

## 四、什么没干好（教训）

1. **数据丢失事故（严重）**：
   用 `git show HEAD > 工作文件` 做对比验证时，覆盖了工作区未提交的改动
   （SuperMapSceneViewer.vue 10539 行版本），一度丢失。最终从 git dangling commit 恢复。
   **教训：任何 `>` 覆盖工作文件的命令都是高危操作，必须先备份；验证类操作不应改动工作区。**

2. **Python 批量删除的边界错误（两次）**：
   用大括号配平脚本删死代码时，两次算错边界（误删 `addGlobeRoadEntity`/`addGlobeFacilityEntity`
   等存活函数，留下悬空代码）。**教训：批量删除必须逐函数确认边界，删后立即跑类型检查。**

3. **js/python 脚本删除逻辑不严谨**：`del lines[791:854]` 的行号偏移计算错误导致二次误删，
   靠备份文件恢复。**教训：行号删除后不可复用原始行号，应基于内容锚点。**

4. **手工启动漏配环境变量**：启动后端时漏了 `JWT_SECRET`，导致整个后端 500、
   前端路由全失效。**教训：手工启动必须与 run-local.bat 的环境变量完全一致。**

5. **run-local.bat 的 uv sync 网络超时卡死**：脚本没有超时退出机制，
   网络差时整个启动流程挂死且无提示。**教训：启动脚本应加超时与失败提示。**

6. **iServer 缓存被清无感知**：今天有人/某流程清空了 iServer output 缓存目录的瓦片，
   但没有留下记录或恢复机制。**教训：iServer 数据目录应纳入版本管理/备份。**

7. **前端部分验证不完整**：playwright 截图诊断多次因页面加载慢/字体加载超时而失败，
   走了不少弯路。**教训：诊断脚本应设宽松超时、避免依赖截图。**
