# 化工园区危险化学品泄漏应急处置流程

> 文档版本：1.0
>
> 适用系统：化工园区危险气体监测、扩散分析、泄漏源溯源、巡检小车和千问应急辅助决策
>
> 适用日期：2026-08-03
>
> 文档性质：辅助决策知识，不是园区综合应急预案、企业专项应急预案、现场处置方案、岗位操作法或 SDS 的替代文件。

## 0. 使用边界

本流程用于把监测告警、视频、工艺、气象、人员定位和现场反馈组织成可审核的处置建议。系统只能输出建议、风险解释、复核问题、通知和记录要求，不能代替现场指挥员发布口令，也不能自动完成停车、切断、联锁旁路、排放、堵漏、冲洗、进入危险区或恢复生产。

处置依据的优先顺序为：

1. 现行法律法规、政府和园区应急指挥机构指令；
2. 企业已备案的综合/专项应急预案和现场处置方案；
3. 现场介质最新版 SDS、工艺卡、联锁逻辑和设备操作规程；
4. 经校验的监测、气象、视频、人员定位和人工检测数据；
5. 本文档和模型建议。

发生冲突时，系统必须提示“以现场授权指挥和最新审批文件为准”，不能自行选择更激进的操作。

## 2. 系统判定原则

### 2.1 不设全国通用的数字处置阈值

可燃气体、毒性气体、氧气、液体化学品和反应失控的报警值必须从企业仪表配置、SDS、工艺风险分析、现场处置方案和园区预案读取。系统不能写死“达到某个 ppm 就疏散”或“低于某个数值即可恢复”。

对每条数据保存：`value`、`unit`、`threshold_source`、`threshold_version`、`timestamp`、`quality`、`calibration_status` 和 `sensor_id`。缺少单位、阈值来源或时间戳时，数据只能作为线索，不能作为安全确认。

### 2.2 告警可信度

| 可信度 | 典型条件 | 系统动作 |
| --- | --- | --- |
| 高 | 两个以上相邻测点同向变化，或传感器与视频/工艺/人工检测一致 | 按真实泄漏处置并持续升级判断 |
| 中 | 单点持续超限，趋势明确，但缺少视频或工艺证据 | 按较高风险隔离、复测和通知，不能降低为安全 |
| 低 | 单点瞬时异常、通信中断、校验过期或数据冲突 | 标记数据降级，安排合规复测；人员安全动作仍优先 |

### 2.3 立即升级条件

出现下列任一项，直接进入园区响应评估，并将“重大紧急级”作为系统候选标签：

- 有人员受伤、失联、中毒、窒息、灼伤或需要专业救援；
- 发生火灾、爆炸、爆燃、喷射火、闪燃或存在明显点火/爆炸风险；
- 介质、泄漏源、泄漏量或危险特性不明；
- 泄漏位于重大危险源、压力容器、液化烃、反应器或关键管廊；
- 浓度、压力、温度或液位快速上升，或者联锁动作结果不明；
- 气团或液体可能越过企业边界、进入人员密集区、道路、雨水系统、污水系统、地下空间或外环境；
- 企业现场处置能力不足，关键消防、检测、通信、冷却、切断或事故池能力失效；
- 相邻企业、道路、居民区、学校、医院或其他敏感目标可能受到影响。

系统中的 LOW/MEDIUM/HIGH/CRITICAL 是辅助决策标签，不等同于生产安全事故等级，也不等同于园区应急预案的 I、II、III、IV 级响应。

## 3. 全流程处置卡

### 3.1 T0 - 接警和保命

值守人员或系统完成以下登记：告警编号、发生/发现时间、企业、装置、坐标、介质、相态、测点、当前值、单位、企业报警阈值、趋势、数据质量、风向风速、视频状态、人员数量和重大危险源标识。

人员安全动作优先于告警确认：

1. 通知现场人员停止无关作业，向上风向或侧上风向撤离；不要穿越可见气团、烟雾、液池和下风向区域。
2. 现场人员不要为核实告警靠近泄漏点，不要进入储罐、沟槽、地坑、地下管廊或其他受污染/缺氧空间。
3. 立即暂停巡检小车靠近告警点，必要时返航；普通人员不得依靠小车替代专业侦检和救援。
4. 有中毒、窒息、灼伤或人员失联时，先报警并请求消防、医疗和专业救援，禁止无防护盲目施救。

### 3.2 T+1 至 T+3 分钟 - 远程核实

只做不增加暴露的核实：

- 对照相邻测点、历史趋势、视频、压力、温度、流量、液位、阀位、联锁、消防和排水状态；
- 查看介质清单和最新版 SDS，确认毒性、可燃性、腐蚀性、反应性、遇水禁忌、蒸气密度和防护要求；
- 调取气象站、风向风速、降雨和扩散模型结果，标记模型假设、更新时间和不确定性；
- 从人员定位和门禁清单核对装置内人数、承包商、访客和失联人员；
- 核对传感器校验、通信、供电和冗余状态，避免把仪表故障当作安全信号。

若关键事实缺失，系统输出缺口列表，同时执行保守动作：隔离、警戒、通知、复测和升级评估。

### 3.3 T+3 至 T+10 分钟 - 隔离和初期控制

由企业授权负责人确认并下达口令，园区指挥中心记录回执：

1. 以泄漏源、扩散方向、低洼处、排水口和人员暴露情况设置警戒区。警戒距离采用企业预案、SDS、风险评估、现场检测和指挥员判断，不由模型臆造固定米数。
2. 停止动火、临时用电、装卸、车辆通行、检维修、受限空间和其他可能引发点火或扩大暴露的作业；特殊作业票状态设为“暂停待复核”。
3. 由授权人员按现场方案确认远程停车、停止进料、紧急切断、关闭区域阀门、切换事故池、启动喷淋/冷却/洗消或其他工程控制措施。
4. 任何阀门、联锁、放空、排放、冲洗、惰化、加水、加抑制剂、堵漏和转输动作必须先确认介质、相容性、工艺条件和授权人；系统只能提出“待确认建议”。
5. 液体泄漏优先防止进入雨水、污水、地下空间和相邻装置。围堵、吸附、收集和覆盖材料必须与介质相容，未知物料不得盲目冲水或混合收集。
6. 可燃介质区域控制火源、车辆和非防爆设备。禁止在不确定危险区使用普通电器、产生火花的工具或可能点火的通讯设备。

### 3.4 T+10 分钟以后 - 专业处置

现场侦检、救援、关阀、堵漏、洗消、转输和环境处置由受训且具备资质和防护条件的专业队伍执行。系统持续显示：

- 可燃气体、毒性气体、氧含量、温度、压力、液位和火焰变化；
- 上风向、侧风向、下风向和边界测点；
- 风向突变、扩散模型重算结果和模型不确定性；
- 火灾、爆炸、储罐受热、设备变形、反应失控和二次泄漏线索；
- 人员清点、伤员位置、救援队伍、PPE、检测仪、洗消点、医疗点和撤离路线；
- 事故池、围堰、排口、雨水闸门、污水系统和外环境采样状态。

监测频率按企业方案、现场指挥要求和仪表刷新能力配置。未配置复核频率时，系统不得擅自承诺固定频率，应显示“按现场预案执行”。

### 3.5 结束和恢复

解除警戒、恢复作业和恢复生产必须分阶段批准：

1. 泄漏源已隔离或修复，物料平衡和残余库存明确；
2. 重点区域、下风向、低洼处、排水系统、设备内部和周边边界完成规定检测；
3. 检测值达到企业预案、SDS、职业卫生和环境管理要求，且趋势稳定，无新增测点异常；
4. 消防、检测、通风、冷却、联锁、通信、供电、事故池和排水设施经功能确认；
5. 受污染设备、废液、吸附材料、洗消水和受污染土壤按批准方案分类收集和合规处置；
6. 人员清点、伤员救治、环境监测、对外报告和现场证据保存完成；
7. 企业工艺、设备、安全、环保和园区指挥人员联合签字，必要时经政府应急指挥机构批准；
8. 完成原因调查、隐患整改、预案修订、物资补充和演练改进。

“告警消失”“单个测点回落”或“现场闻不到气味”都不能作为恢复依据。

## 4. 分介质处置规则

### 4.1 可燃气体或蒸气

- 先撤离、警戒、控制火源和车辆，再由授权人员判断远程停车/切断；
- 监测浓度、趋势、风向、压力、相邻点位和可能的点火源；
- 不能用普通通风把气体推向人员、道路、办公区或敏感目标；
- 出现火焰、爆鸣、爆燃、浓度快速升高、压力上升或无法切断时扩大警戒并升级；
- 灭火或冷却方式以介质 SDS、消防方案和消防指挥为准，不由模型自行选择。

### 4.2 有毒气体或有毒蒸气

- 以有毒泄漏处理，撤到上风向/侧上风向，禁止无防护人员进入气团；
- 是否就地避险、关闭门窗和新风系统，按园区预案、风向和建筑条件由指挥员决定；
- 专业队伍必须根据介质选择呼吸防护、皮肤防护、检测、洗消和医疗分诊；
- 伤员移出污染区后按医疗预案去污、呼吸支持和转运，不在未知介质情况下擅用特定解毒剂；
- 下风向检测持续异常、出现人员症状或气团越界时，立即升级园区响应。

### 4.3 液体、浆体或固体泄漏

- 先确认名称、浓度、温度、包装/设备、预计量和 SDS 禁忌；
- 停止可能增加流量的输送、装卸和进料，关阀/停泵由授权人员执行；
- 使用相容的围堵、吸附、收集和覆盖材料，防止进入排水、土壤和地下空间；
- 遇水反应、强放热、产气、聚合、强氧化或腐蚀性物料不得盲目冲洗和混合；
- 越过围堰、进入外环境、出现蒸气云/发热/冒烟/起泡，或量不明时升级。

### 4.4 介质不明、混合泄漏或气液两相泄漏

- 立即按较高风险处置，远程核对容器、管线、物料台账和作业票；
- 禁止闻气味、徒手接触、取样、开盖、进入低洼处或用水试验；
- 同时评估中毒、窒息、可燃、腐蚀、反应和环境风险；
- 只有在专业检测、SDS/物料信息和现场指挥确认后，才能选择相应的灭火、稀释、收集、堵漏或洗消方法。

## 5. 园区协同和报告

园区指挥中心至少维护以下责任链：企业值班负责人、园区应急负责人、消防救援、医疗救护、工艺设备、电气仪表、环保监测、交通疏导、通信和物资保障。

系统应生成但不能代替人工确认的通知内容：

- 事件编号、发现/发生时间、企业/装置/坐标和介质；
- 现场已确认事实、未确认事实、数据来源、数据质量和最新时间；
- 人员伤亡/失联、风向风速、扩散方向、当前警戒和受影响区域；
- 已执行动作及执行人、待授权动作、资源需求和下一次复核时间；
- 是否可能跨企业、越界、进入环境、涉及重大危险源、压力容器或敏感目标；
- 向企业、园区和有关政府部门报告的时间、联系人和回执。

报告级别和时限以法律法规、事故报告制度、园区预案和属地要求为准，系统不得编造“统一几分钟内报告”的规则。

## 6. 系统输出契约

千问每次必须先输出最关键的人员安全动作，并显式区分事实、判断、建议和执行回执：

```text
【告警结论】
告警编号：{id}；类型：{gas/liquid/unknown/mixed}；企业/区域：{location}；时间：{time}
初步风险：{LOW/MEDIUM/HIGH/CRITICAL}；置信度：{high/medium/low}
依据：{sensor/video/process/weather/manual}；数据质量：{normal/degraded/unknown}
标准/知识引用：{条目编号、版本、适用范围}

【现在先做】
1. 人员：{撤离、清点、救援和集合点动作}
```

## 8. 闭环记录和上线验收

每次事件必须保留：告警原始值、阈值来源和版本、模型输入、模型输出、引用依据、人工审核人、通知回执、执行回执、检测数据、关键口令、现场照片/视频索引、恢复批准和整改闭环。

上线前至少验证：

- 介质未知、SDS 缺失、单位缺失、通信中断、传感器漂移和多点冲突；
- 可燃气体、有毒气体、缺氧、液体进入排水、跨企业扩散、火灾爆炸和极端天气复合告警；
- 现场人员撤离、清点、伤员转运、巡检车暂停/返航、通知和回执；
- AI 建议与实际执行状态分离，所有高风险动作有人审、有授权、有回执；
- 阈值、疏散距离、PPE、灭火剂、洗消剂和恢复条件均能回溯到企业预案、SDS 或正式标准；
- 预案版本、标准版本、物资状态、演练记录和知识库更新时间可查询；
- 千问不可用时，规则兜底仍优先执行人员安全、隔离、复测、通知和升级，不输出危险操作指令。
