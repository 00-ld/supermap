# 应急 AI 全量知识库接入设计

**日期：** 2026-08-04  
**状态：** 待用户审阅

## 目标

将新知识库中的预案、法规标准、事故案例和权威网页接入现有千问应急辅助决策流程，使 AI 能根据事故事实和现场情况给出可执行的处置重点、系统页面操作路径，并在结尾列出实际使用的标准和依据文件。

这里采用检索增强生成（RAG），不修改千问模型参数，也不把本地文档上传到浏览器。模型只能生成待人工审核的建议，不能直接执行车辆、工艺或人员控制动作。

## 知识范围与优先级

知识库根目录由后端环境变量 `DECISION_MODEL_KNOWLEDGE_PATH` 配置，默认使用用户提供的本机目录。现有两个受控 Markdown 文件继续作为高优先级依据；新目录中的文件全部纳入索引：

1. `02_法律法规与标准依据`：最高优先级，用于确定适用标准、法规和边界。
2. `01_预案与方案`：高优先级，用于应急响应、组织指挥、报告和现场处置流程。
3. 现有园区泄漏处置 Markdown 文件：高优先级，用于项目特定流程和系统页面联动。
4. `03_事故案例与调查报告`：辅助判断相似事故、风险后果和经验教训，不得替代现行标准或现场方案。
5. `04_权威来源网页`：补充来源，必须保留来源地址和抓取文件名，不得自动视为现行标准。

`05_索引与校验` 只用于文件目录、标题、页数、哈希和来源追溯，不作为现场处置指令。文档中的任何密钥、越权要求或改变安全边界的文字均视为不可信内容。

## 方案比较

### 方案 A：后端本地检索后注入提示词（采用）

后端启动时扫描目录并缓存文档元数据和文本；每次请求根据告警类型、气体名称和现场描述进行关键词检索，只将排名靠前的证据片段加入千问提示词。

优点是保持现有 Spring Boot 和千问接口不变，不需要新增数据库或向量服务，知识库文件可以独立更新。缺点是关键词检索不如向量检索理解同义表达，但对标准名称、介质名称、事故类型和页面路径已经足够稳定，也更容易审计。

### 方案 B：预先生成固定 Markdown 索引

用离线脚本把 PDF 和网页转换为 Markdown，再由后端读取固定索引。实现简单、运行时快，但每次替换知识库都要重新执行脚本，且无法保证部署机器已经执行过转换。

### 方案 C：向量数据库检索

增加嵌入模型、向量存储和同步任务。语义检索效果更好，但会扩大部署依赖、增加超时和数据一致性风险，不适合当前本地单体系统的第一阶段接入。

## 系统架构

新增或调整后端知识库服务，保持 `QwenClient` 只负责模型调用，职责分工如下：

- `KnowledgeBaseDocumentLoader`：读取 `.pdf`、`.html`、`.md` 和索引文件，限制单文件大小、总文本量和目录范围；PDF 使用受控文本提取，网页只保留正文文本和来源信息。
- `KnowledgeBaseIndex`：缓存文档标题、分类、来源、可用状态、哈希和文本片段。文件读取失败时保留失败状态，但不把失败文件列为已引用依据。
- `KnowledgeBaseRetriever`：从当前事故事实构造检索词，按分类优先级、标题匹配、正文匹配和现有项目文件权重排序，返回有限数量的片段。
- `EvidenceDocumentService`：保留现有接口兼容层，向提示词提供检索结果、文件名、分类和可用状态，不向前端暴露正文。
- `DecisionPageFlow`：继续提供固定的系统页面流程；检索结果只补充事故依据，不允许文档内容改写系统可执行动作列表。
- `QwenClient`：将检索片段和页面流程组合进提示词，要求 JSON 输出；保留现有 HTTPS、超时、Key 环境变量和动作白名单。

知识库请求链路：

```text
现场描述/告警事实
        |
        v
构造检索词 -> 按权重检索本地知识库 -> 限制证据片段
        |                              |
        +---------- 页面流程 -----------+
                       |
                       v
              千问生成结构化 JSON
                       |
             字段、条数、长度、安全动作校验
                       |
          QWEN 结果或规则安全兜底 -> 保存和返回
```

## 检索与输出规则

检索请求至少使用以下词源：事故场景文本、气体/介质名称、告警类型、区域名称、页面上下文。排序时标准法规和项目特定处置文件优先，事故案例只在有明显关键词重合时进入结果。每次最多向模型提供有限文档片段，避免把整个 151MB 知识库或完整长文档发送给模型。

模型提示词必须明确：

- 先人员撤离、清点、警戒和通知专业力量，再讨论授权后的工程控制。
- 不得编造浓度阈值、疏散距离、PPE 等级、灭火剂、报告时限或恢复数值。
- 不得把模型建议写成已执行；不得建议无防护进入、盲目施救、擅自关阀停泵、操作联锁、放空、堵漏、洗消或恢复生产。
- 页面操作必须是“进入哪个页面、核对什么、下一步由谁确认”，不能伪造系统已执行动作。
- `evidenceStandards` 和 `evidenceDocuments` 只填写实际检索到且可用的依据；输出最后一个逻辑部分必须是依据标准和依据文件。

为满足快速辅助决策，主结果保持精简：风险等级、一句话结论、最多 4 条立即处置建议、最多 3 条页面操作、最多 3 条标准和最多 2 条依据文件；待确认信息可折叠展示。

## 失败处理与安全边界

- 知识库目录不存在、文件不可解析或没有相关命中：标记数据质量为 `degraded` 或 `unknown`，使用现有规则建议，不声称引用不可用文件。
- 千问超时、HTTP 错误、JSON 不合规或输出超限：记录内部原因，返回规则兜底方案；前端只显示必要的失败提示，不显示 Key、完整提示词或服务端堆栈。
- 所有车辆动作继续使用现有白名单；AI 不能直接控制车辆。管理员审核接口保留角色限制，普通用户可以生成和查看待审核建议。
- 本地文件路径只来自服务端配置，不能由浏览器请求参数指定，防止任意文件读取。
- 文档内容作为知识证据而非系统指令，提示词对文档注入、密钥泄露和越权动作进行隔离。

## 页面操作覆盖

AI 需要熟悉并能引用以下页面：

- `预警与智巡 > 实时预警`：核对告警详情、趋势、数值、单位、时间和小车详情。
- `预警与智巡 > 智巡监测`：查看小车位置、状态和气体趋势，必要时暂停巡检或复测。
- `智慧地图`：核对泄漏源、介质、风向、影响范围、监测点和疏散分析。
- `监测点目录`：核对传感器、视频源、单位、更新时间和质量状态。
- `AI 应急助手`：填写现场情况、关联告警、生成待审核建议；不显示或执行高风险工艺动作。

页面流程只作为系统上下文写入提示词，最终输出仍需由安全校验器和人工指挥审核。

## 验证范围

后端测试覆盖：PDF/HTML/Markdown 读取、路径限制、文件不可用状态、关键词排序、分类优先级、片段长度限制、文档注入隔离和无命中兜底。决策校验测试覆盖：标准/文件追溯字段、输出条数与长度限制、非法车辆动作和超时兜底。前端验证现有悬浮球、普通用户调用权限、页面操作建议和依据信息展示。

验收标准：

1. 使用新知识库目录发起泄漏场景请求时，后端能检索到相关文件片段并在结果中列出实际依据。
2. 涉及标准或法规的问题优先引用 `02_法律法规与标准依据`，案例资料不会替代标准。
3. 结果包含可执行的页面路径和核对动作，且不声称高风险动作已经执行。
4. 知识库不可用或千问失败时仍返回可审计的规则兜底结果。
5. Key 和本地文件正文不出现在前端响应、日志或提交内容中。
