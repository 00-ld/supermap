# 超图杯系统分工规划：SuperMap 与自研能力边界

更新时间：2026-07-13

## 1. 核心原则

本项目按“超图杯参赛作品”推进，不按普通化工园区管理系统推进。

评委必须能从第一屏、演示流程、技术文档和追问回答中明确看到：

- SuperMap 产品链承担 GIS 主干能力。
- 自研系统承担化工安全业务、算法内核、数据编排和交互体验。
- 不是在 Vue 页面里简单嵌一个 SuperMap 页面，也不是把所有已有能力推倒重写。

一句话边界：

> SuperMap 做空间底座、数据服务、地图/三维表达和空间分析承载；我们自己做业务系统、算法服务、数据融合、应急流程和参赛叙事。

## 2. 必须使用 SuperMap 的部分

这些部分是超图杯评审最容易看到和追问的地方，必须优先 SuperMap 化。

| 模块 | 必用 SuperMap 产品/能力 | 交付形态 | 完成标准 |
|---|---|---|---|
| 三维数字孪生入口 | iDesktopX、iServer 3D、iClient3D WebGL | `/screen` 原生三维场景 | 可见园区三维模型，不是黑屏/空 WebGL；S3M 瓦片请求成功 |
| 三维瓦片处理 | iDesktopX 2026 | 桌面端处理记录、截图、SCP/S3M 清单 | 有 iDesktopX 加载、定位、检查截图 |
| 三维场景服务 | iServer Realspace / S3M config | iServer 三维服务 URL | Web 端直接消费 iServer 服务，不只 iframe |
| 二维地图底图 | SuperMap iClient2D、iServer REST Maps | `/smart-map` 二维底图层 | 页面显示 SuperMap 服务状态和瓦片请求证据 |
| GIS 数据发布 | iDesktopX 数据集 + iServer REST 服务 | 园区边界、道路、建筑、传感器点、风险区服务 | 前端逐步减少本地静态 GIS 数据依赖 |
| 统一资源管理 | iPortal | 门户资源、大屏、服务目录 | iPortal 作为资源管理和展示入口，不作为唯一系统入口 |
| 空间分析表达 | iServer 空间分析或 SuperMap 图层表达 | 缓冲区、危险区、等值线、路径图层 | 算法结果转成可解释 GIS 图层 |
| 参赛报告证据 | SuperMap 产品截图和服务链路图 | PPT、报告、视频素材 | 能说清 iDesktopX -> iServer -> iPortal/iClient -> Web 系统链路 |

## 3. 应该自研的部分

这些是作品创新点，不应该为了“看起来更超图”硬换掉。

| 模块 | 自研内容 | 为什么自研 |
|---|---|---|
| 气体扩散算法 | FastAPI 扩散模拟、浓度场生成、时序帧 | 这是作品核心安全算法，SuperMap 负责承载和可视化结果 |
| 泄漏源反演 | 粗搜索、粒子滤波、深度代理校准 | 这是创新算法，不应降级成普通 GIS 查询 |
| 疏散路径规划 | D* Lite / A* / 风险避让路径 | SuperMap 表达道路和危险区，自研算法做决策 |
| YOLO 图像识别 | 人员/巡检图像识别 | 属于多源感知能力，SuperMap 只接收识别结果为空间事件 |
| Java 后端 | 用户、业务数据、告警、传感器、车辆、权限 | 业务系统不需要替换成 SuperMap |
| MySQL 数据库 | 业务表、传感器读数、告警历史 | 与 SuperMap 空间数据服务互补 |
| 前端业务交互 | Vue 页面、面板、流程、表单、回放控制 | iClient 提供地图能力，业务体验仍由前端掌控 |
| 报告/答辩逻辑 | 技术路线、创新点、边界说明 | 防止把仿真数据、公开数据或演示服务说成现场生产系统 |

## 4. 当前系统页面分工

| 页面/入口 | 超图承担 | 自研承担 | 后续改造方向 |
|---|---|---|---|
| `/screen` 三维入口 | iClient3D 加载 iServer S3M 场景 | 算法健康、算法操作面板、应急态势 UI | 修掉重复图层和资源 500；加入真正算法执行结果叠加 |
| `/smart-map` 智慧地图 | iClient2D/iServer REST Maps 底图 | Canvas 业务图层、扩散/溯源/疏散交互 | 发布园区二维专用 iServer 服务后替换通用 World 底图 |
| 数字园区/首页 | SuperMap 三维或 iPortal 资源入口 | 业务导航和系统说明 | 第一屏突出 SuperMap 数字孪生，不做普通后台首页 |
| 预警与智巡 | 可接入 SuperMap 事件点、巡检轨迹图层 | 告警规则、YOLO、巡检流程 | 把识别结果转为空间事件点 |
| 人员信息管理 | 一般不需要 SuperMap | 用户、角色、权限 | 不强行 SuperMap 化 |
| iPortal 大屏 | iPortal MapDashboard | 系统跳转和演示组织 | 作为展示资源，不替代自研 Web 主入口 |

## 5. 算法结果如何 SuperMap 化

算法不能只显示“在线”，必须变成空间成果。

| 算法 | 自研输出 | SuperMap 表达 |
|---|---|---|
| 扩散模拟 | 浓度网格、时间序列、风险范围 | 二维热力/等值线、三维半透明云团、危险区图层 |
| 泄漏源反演 | 候选源点、概率评分、估计坐标 | 候选点图层、概率圆/缓冲区、高亮疑似设施 |
| 粒子滤波 | 粒子集合、收敛路径、置信度 | 粒子散点图层、收敛轨迹、置信椭圆 |
| 疏散规划 | 路线点串、避让区、耗时 | iClient 路线图层、阻断区、安全出口标注 |
| YOLO 识别 | 人员框、风险事件、图片元数据 | 人员事件点、巡检轨迹、告警空间定位 |

## 6. 数据来源与建设方法

参赛材料中必须把“数据从哪里来、怎么处理、哪些是真实数据、哪些是仿真/公开数据”说清楚。不能把演示数据包装成现场生产数据。

| 数据类型 | 可用来源 | 处理方法 | SuperMap 承担 | 需要说明的边界 |
|---|---|---|---|---|
| 园区三维模型/瓦片 | 现有 `园区大屏部署`、S3M/SCP 文件、iDesktopX 处理成果 | iDesktopX 检查坐标、图层、材质、瓦片范围，发布到 iServer 3D | 三维数据检查、缓存发布、iClient3D 加载 | 若不是倾斜摄影，报告中写“三维模型/白模/S3M 瓦片”，不写“真实倾斜摄影” |
| 二维底图 | iServer `map-world` 临时服务、后续园区二维专题服务、天地图/OSM 参考 | 先用可访问服务保底，后续用 iDesktopX 整理园区边界、道路、建筑、传感器点并发布 | REST Maps、专题图、空间查询 | OSM/天地图属于外部公开数据，不能写成自采测绘 |
| 道路网络 | 现有前端道路数据、OSM 路网、手工矢量化园区道路 | 统一坐标，抽取节点/边/通行代价，生成路径规划图 | 道路图层发布、网络/缓冲分析可选 | 自研 D* Lite/A* 做动态风险避让，SuperMap 可做基础网络分析对照 |
| 传感器点 | 演示传感器布设、仿真采样、手工观测样本 | 建立点位表，包含坐标、高度、气体类型、读数、时间戳 | 点图层、属性查询、空间筛选 | 没接真实硬件时写“仿真采样/演示采样” |
| 危险源/装置 | 园区设施清单、模型标注、手工整理 | 形成装置点/面图层，绑定化学品和风险等级 | 设施图层、缓冲区、范围查询 | 未经企业确认的数据写“示例装置数据” |
| 气象数据 | 手工输入、公开气象、仿真风场 | 转换为风向、风速、稳定度等算法参数 | 可作为时空属性叠加显示 | 公开气象不等同园区微气象实测 |
| 巡检图像/视频 | 现有演示图片、公开样例、手工拍摄 | YOLO 识别人员/风险事件，落成空间事件点 | 事件点、巡检轨迹、告警定位 | 公开样例必须标注来源口径 |

建设顺序：

1. 先保证三维 S3M 和二维底图在 Web 端可稳定打开。
2. 再把道路、建筑、传感器、危险源做成 iServer 可发布的二维专题服务。
3. 然后把算法输入输出统一成 GeoJSON / JSON，再由 iClient2D/iClient3D 显示为空间图层。
4. 最后在 iPortal 管理资源，把三维场景、二维服务、专题图、大屏和 Web 入口组织成参赛资源目录。

## 7. 算法分层：哪些用 SuperMap，哪些自己做

原则：GIS 标准空间算子优先使用 SuperMap，化工安全推理和应急决策算法保留自研。

| 能力 | 推荐归属 | 说明 |
|---|---|---|
| 缓冲区分析 | SuperMap 内置 | 泄漏点周边影响半径、危险源保护距离、传感器覆盖范围 |
| 空间查询/叠加分析 | SuperMap 内置 | 判断传感器、道路、建筑是否落入危险区 |
| IDW/Kriging 插值、等值线 | SuperMap 内置优先 | 用传感器读数生成浓度面、等值线，可作为自研扩散模型的对照 |
| 专题图/热力图/分级渲染 | SuperMap 内置或 iClient 表达 | 用于风险等级、告警强度、人员密度展示 |
| 基础网络分析 | SuperMap 内置可选 | 做普通最短路或可达性分析，作为疏散算法对照 |
| 气体扩散模型 | 自研 | 体现化工场景创新，输出浓度网格/风险区给 SuperMap 展示 |
| 泄漏源反演 | 自研 | 粗搜索、粒子滤波、置信度估计属于作品核心算法 |
| 动态疏散规划 | 自研为主，SuperMap 对照 | D* Lite/A* 根据扩散风险动态调整路径，SuperMap 提供道路和空间约束 |
| YOLO 风险识别 | 自研 | 识别结果转为空间事件，交给 SuperMap 地图表达 |
| 多源事件融合 | 自研 | 把传感器、视频、人工上报、算法结果编排成应急事件流 |

答辩口径：

> SuperMap 提供空间数据底座和通用 GIS 算子，自研算法负责危险气体扩散、泄漏源反演和动态疏散决策。两者通过标准空间数据接口衔接，最终把算法结果落到二维地图和三维场景中。

## 8. 移动端开发思路

移动端不建议一开始就做完整原生 App。短期先做 H5 移动端，保证能演示现场处置流程；长期再考虑 SuperMap iMobile 原生能力。

| 阶段 | 技术路线 | 主要功能 | SuperMap 使用方式 | 完成标准 |
|---|---|---|---|---|
| 短期 | Vue H5 / PWA | 告警接收、地图定位、附近风险区、疏散路线、处置打卡 | iClient2D 加载 iServer 地图和专题图 | 手机浏览器可打开，能看风险区和路线 |
| 中期 | H5 + 设备能力 | GPS 定位、拍照上传、巡检上报、离线缓存少量任务 | iServer REST 查询、地图截图、空间查询结果 | 现场人员能提交事件并回传坐标 |
| 长期 | SuperMap iMobile 原生 App | 离线地图、原生定位、移动采集、巡检轨迹 | iMobile 加载离线/在线地图服务 | 有安卓安装包、离线数据包和采集流程 |

移动端页面建议只做 4 个核心页：

1. 应急首页：当前事故、风险等级、距离危险区多远。
2. 移动地图：SuperMap 二维底图、危险区、当前位置、安全出口、推荐路线。
3. 巡检上报：拍照、选择事件类型、自动带坐标和时间。
4. 任务处置：接收疏散/封控/巡检任务，提交完成状态。

## 9. 结果可信性验证步骤

参赛时不能只说“算法能运行”，要展示“结果为什么可信”。验证分为数据验证、算法验证、GIS 表达验证、系统回归验证和人工复核五层。

### 9.1 数据验证

| 验证项 | 方法 | 证据 |
|---|---|---|
| 坐标一致性 | 在 iDesktopX 和 Web 端分别检查同一建筑、道路、传感器点位置是否重合 | iDesktopX 截图、Web 截图、坐标记录 |
| 瓦片完整性 | 检查 S3M/SCP 加载范围、材质、图层名称、iServer `.s3mb` 请求状态 | iDesktopX 截图、浏览器网络请求 200 记录 |
| 属性完整性 | 抽查传感器、道路、设施是否有坐标、类型、时间、风险等级等必要字段 | 数据表截图、导出 JSON/CSV |
| 数据来源口径 | 为每类数据标注“实测、公开、仿真、手工整理” | README、报告数据来源表 |

### 9.2 算法验证

| 算法 | 验证方法 | 通过标准 |
|---|---|---|
| 扩散模拟 | 做物理不变量测试：浓度非负、随距离衰减、风向下游风险更高、总量变化合理 | 自动测试通过，异常输入能返回错误信息 |
| 浓度插值/等值线 | 用 SuperMap IDW/Kriging 或等值线结果与自研扩散结果对照 | 高风险区域空间位置大体一致，差异能解释 |
| 泄漏源反演 | 用已知泄漏点生成仿真观测，再反推源点 | 估计点与真实点距离小于设定阈值，置信区覆盖真实源 |
| 粒子滤波 | 观察粒子从分散到收敛，记录误差随迭代下降 | 收敛曲线稳定，不出现发散或 NaN |
| 疏散规划 | 设置危险区、阻断道路、安全出口，对比普通最短路和风险避让路径 | 路线不穿越高危区，耗时/距离在合理范围 |
| YOLO 识别 | 用标注样例或公开样例计算识别准确率、漏检误检样例 | 给出 Precision/Recall 或至少给出样例混淆表 |

已有代码验证入口应纳入报告：

```powershell
cd G:\竞赛\超图杯\code\chemical-main
uv run --no-sync python -m algorithm.diffusion.test_physical_invariants
uv run --no-sync python -m algorithm.inversion.validate_particle_filter
uv run --no-sync python -m algorithm.planning.test_dstar_lite
uv run --no-sync python -m tests.test_forward_model
```

### 9.3 GIS 表达验证

| 验证项 | 方法 | 证据 |
|---|---|---|
| 算法结果落图 | 点击算法按钮后，检查扩散区、源点、疏散路线是否叠加到 SuperMap 场景 | 操作截图、接口响应 JSON、图层状态 |
| 空间位置正确 | 抽查结果坐标是否落在园区范围内，是否和道路/建筑/传感器相对位置合理 | 坐标点截图、地图量测截图 |
| 图层可清除可重复 | 连续运行、清除、重跑，确认不会重复堆叠或残留旧结果 | 浏览器截图、控制台无重复图层错误 |
| 二三维一致 | 同一事故在二维 `/smart-map` 和三维 `/screen` 中位置一致 | 二维截图、三维截图 |

### 9.4 系统回归验证

每次参赛演示前执行以下检查：

1. 前端构建通过：`npm run typecheck:strict` 和生产构建。
2. 算法服务健康检查通过：`/api/health` 返回扩散、反演、疏散能力清单。
3. 三维入口打开后能看到真实模型，不是黑屏、空场景或单纯 iframe。
4. 浏览器控制台没有项目可控的 SuperMap 重复图层、资源 404/500、算法接口失败。
5. iServer 服务 URL 可访问，关键 `.s3mb`、地图瓦片或图片请求为 200。
6. 算法执行产生可保存的输入、输出和地图截图。

### 9.5 人工复核与报告证据

人工复核不是让用户重复开发，而是用于比赛可信性背书。

| 需要用户确认 | AI 可以代做 |
|---|---|
| 数据来源口径是否能公开写入报告 | 整理数据来源表、把敏感字段脱敏 |
| 三维模型是否符合园区实际布局或演示设定 | 截图、标注、生成对比说明 |
| 算法阈值是否符合答辩口径 | 跑测试、输出误差表和可视化 |
| PPT 中哪些能力写“已完成”、哪些写“规划中” | 根据验证结果生成事实边界清单 |

最终每个核心演示功能都要留下四类证据：

1. 输入：接口请求参数、传感器读数、事故设定。
2. 计算：算法响应、耗时、误差或置信度。
3. 空间结果：二维/三维 SuperMap 图层截图。
4. 复核结论：是否通过、问题、下一步改进。

## 10. 实施优先级

### P0：演示不能出错

- `/screen` 控制台不能有我们可控的 SuperMap 重复图层错误。
- 三维场景必须稳定可见。
- 算法面板必须至少能触发健康检查和一个真实算法请求。
- 截图不能是黑屏、空场景或只显示状态卡片。

### P1：SuperMap 主链路闭环

- iDesktopX 处理数据。
- iServer 发布二维/三维服务。
- iPortal 管理资源。
- Web 用 iClient2D/iClient3D 原生消费服务。
- 报告中有链路图、截图和服务 URL 证据。

### P2：算法空间化

- 扩散、反演、疏散结果不只在业务面板里显示，必须落到地图/三维场景。
- 能导出算法输入输出 JSON，便于报告说明“算法封装”。

### P3：加分项

- iPortal 大屏修通并纳入演示。
- 移动 H5 现场处置端。
- iServer 空间分析服务承接缓冲区、查询、专题图等 GIS 算子。

## 11. 用户与 AI 分工

### AI 直接做

- 读代码、改前端、改后端、启动服务、跑测试。
- 对接 iServer/iPortal/iClient。
- 整理截图、处理记录、README、报告素材。
- 发现控制台错误后定位并修复可控问题。
- 把算法结果包装成地图图层和演示流程。

### 用户只需要做

- 提供或确认无法由 AI 操作的桌面端授权/登录/验证码。
- 在 iDesktopX 中需要人工确认的高危发布动作。
- 最终选择参赛叙事口径、PPT 风格和演示重点。

### 必须先确认的动作

- 删除重要数据。
- 外发私密文件或服务器凭据。
- 修改生产服务器配置。
- 重置许可、重装 SuperMap 服务、购买服务。

## 12. 当前事实边界

- 三维 Web 端已经能看到 SuperMap3D 场景，但仍需修掉重复图层错误和资源 500。
- 二维已经接入 SuperMap iClient2D，但当前使用的是通用 `map-world/World`，不是园区专用二维服务。
- 园区业务图层仍大量来自前端 Canvas 和本地数据，后续要逐步发布成 iServer 服务。
- 算法服务在线不等于算法已集成到 SuperMap 场景；必须补“点击运行 -> 算法响应 -> 图层表达”的闭环。
