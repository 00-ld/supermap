## 一、完成了什么

### 1. 算法点位数据源切换（核心诉求，已完成）

- 扩散浓度采集点位、溯源观测点位全部切换为 **B 套模型绑定点位**（iServer `MonitorPoints_4490`，1072 点中 887 个气体点位 → 高低位去重保留低位 → **583 个唯一位置**）。
- 删除 A 套（DOM 底图系 81+29 点）**前端数据 + 后端数据全链**：
  - 前端：`realSensorLayout.ts`、`monitoringSensorStandard.ts`、`api/sensor.ts`、`api/sensorReadings.ts`、`api/monitorPoint.ts`、`api/simulationMonitoring.ts`、`useSmartMapSensorReadings.ts`（SSE）、监测点目录页 `monitor/index.vue`、`layout/monitor.vue`、路由。
  - 后端：sensor/sensor_reading/monitor_point 三表（init.sql/schema/种子）、32 个 Java 文件（Controller/Service/Mapper/POJO/DTO/测试）、SSE 链（RealtimeSensorReading/Stream/Ticket）、SimulationMonitoring 读数端点、MonitoringData 的 sensor 指标。
- **泄漏源改用模型系锚点**（spatial-assets.4490.json 已配准 6 源），不再用底图系设施中心。

### 2. 算法坐标系统一（完成）

- 定义 `ALGORITHM_FRAME`（X=east+80, Y=-north+420，网格 1000×540，mapMetersPerUnit=1），B 套 583 点全部落网格（x∈[14,959], y∈[17,503]），泄漏源 6 个全部落网格（X∈[35,86], Y∈[71,352]）。
- 坐标换算经独立脚本逐点复核 **583 点全部一致**。

### 3. B 套点位三维零偏差（完成，但未实测）

- B 套点位三维显示仍按 **Wgs84 原值放置**（`devicePoint` 层），模型绑定（点击模型 → ModelName 查询）完全不受影响。
- 算法 overlay（扩散体元/溯源 KDE/后验粒子/源点标记/泄漏源选择）渲染前统一 `algorithmToLocal` 逆变换回模型真实位置（10 处渲染入口）。

### 4. 2D 显示适配（完成后又修了一轮）

- 2D 小地图（SmartMap2DInset）：视口切算法系，底图按真实位置放置。
- **主 2D 画布（useSmartMapRenderer）修复**：算法层（传感器/扩散/溯源/源点）绘制前逆变换；视口北扩 420m 覆盖模型区；点击命中与手动布点坐标转算法系。
- 扩散 payload 的 map 改 ALGORITHM_MAP（初版遗漏，2D 点位乱了之后发现并修复）。

### 5. 验证

- `vue-tsc` typecheck ✓、`vite build` ✓（5995 模块）、`validate:spatial-assets` ✓、后端 `mvn test` 133 用例 0 失败 ✓、583 点坐标逐点复核 ✓。

## 三、什么没有完成

1. **浏览器实测验收**——所有验证停留在编译/静态层，未跑起前后端人工确认。
2. **3D Tiles 旧演示模式**（`shouldUseThreeDTiles`）下 B 套点位无模型锚定：`sensorSceneMapPoint` 直接算法系逆变换，点位落在底图系映射位置，与 3D Tiles 模型（郑州，不同模型）不对应。旧模式非主路径，但技术上未完成适配。
3. **传感器持久化**：原后端 sensor 表删除后，智慧地图传感器改纯前端内存，刷新页面布点重置为 B 套默认——"持久化"能力丢失（符合"无后端点位表"定位，但功能上未替代）。
4. **真实硬件读数接入溯源**：sensor_reading 表与 SSE 链删除后，实测数据→溯源观测的适配器不存在（当前溯源输入全部来自扩散帧重采样，模拟闭环）。
5. **移动端/其他页面（car 巡检）**：仅做了 overview 字段可选兼容，未逐页实测。
6. **风险网格/设施区与模型的错位**：2D 底图/设施标注按用户决策"本次不动"，错位如实呈现但未对齐。

## 四、什么的完成效果不好（质量欠佳处）

1. **2D 主画布呈现效果差**：
   - B 套点位/云团显示在**底图北缘上方的空白区**（底图与模型真实错位 ~420m 的如实呈现），底图与算法内容分离，视觉上"点位不在园区图上"。
   - 这是"2D 标注不动"决策 + 模型错位的必然结果，但用户观感是"点位和地图对不上"。**要彻底解决需把底图/设施整体迁移对齐模型系（原决策的"一并迁移"选项）**。
2. **2D 小地图底图大部分在视口外**：视口 = 算法系（1000×540），底图（1587×947）只有北缘条带落在视口内，小地图上底图几乎不可见，云团显示在空白背景上。
3. **手动布点坐标转换是事后补丁**：capture 处转算法系，但手动录入表单（坐标输入框）仍是底图系习惯，混用易困惑；批量导入（Agent B 改的本地追加）坐标语义未验证。
4. **渲染层坐标转换靠"每个入口手动包一层"**：10 处渲染入口 + 2 处命中 + 2 处布点分别补 transform，没有统一抽象（如"算法坐标包装函数"），后续新增渲染点易遗漏——本次已踩一次（2D 画布漏改导致"点位乱了"）。
5. **后端删除的连带影响**：home/screen/car/emergency 页面的监测概览传感器指标归零（overview 改造为返回空），页面显示"传感器 0 个"类信息，观感突兀（类型上兼容，视觉上未处理）。
6. **生成数据与运行时转换双份实现**：生成脚本（cjs）与运行时（supermapGeoreference.js）各有一套转换公式，靠注释约定同步，改一处忘另一处会静默错位。
