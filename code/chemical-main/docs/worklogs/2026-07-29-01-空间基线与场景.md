# 阶段 1-2：空间基线、出入口与场景

## 目标

在不覆盖现有脏工作树的前提下，把三维展示统一到 EPSG:4490，并保证附属场景失败时主场景不被清空。

## 基线证据

- 本地端口：前端 `5173`、Java `8081`、iServer `8090`。
- 主场景 config：`huangong_4490`，CRS 为 `epsg:4490`。
- 主场景包络：`113.52251344784995,34.809569875817076` 至 `113.5490252942224,34.82777430787187`。
- iServer 当前只有主场景和一个历史 3D 服务；六个附属服务未发布。
- 实施后截图：[主场景近景](./phase-screen-after.png)、[附属服务失败后主场景保留](./phase-scene-safe-fallback.png)。

## 变化

- 建立 `spatial-assets.4490.json`，固定 7 个场景和 4 个出入口的 ID、服务、对象绑定、4490 锚点及相机。
- 三维显示锚点改为已发布 S3M config 的 `113.535771,34.818673`，4547 只保留在分析适配层。
- 出入口点击使用目标点局部 ENU 计算相机位置、方向和 up；FOV、near/far、距离均为米制近景参数。
- 场景切换前先请求 config，并在能解析到首层 S3M 资源时继续探测瓦片；预检失败不删除当前图层。
- 主场景使用注册目标点进入近景，附属模型按包围球和清单参数限制距离。

## 问题与解决

- 问题：历史三维锚点位于 `113.569463,34.76965`，与当前已配准场景相距约 7.4 km。
- 根因：旧 3D Tiles 试配锚点继续被通用转换链消费。
- 解决：显示锚点改为主场景 config 的真实插入点，并用空间清单做唯一入口。
- 问题：六个按钮会先清空主场景，再尝试不存在的服务。
- 解决：增加资源预检门禁；实测点击“加工厂房”后主场景仍保持显示。

## 验证与回滚

- `npm run validate:spatial-assets`：7 场景、4 出入口通过。
- Playwright/Edge：`/#/screen` 200，无 page error，主模型近景可见。
- 回滚：设置 `VITE_FEATURE_SCENE_REGISTRY_4490=false`，恢复旧环境变量场景列表。
