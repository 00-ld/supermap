设计约束：

- `ComponentId` 唯一标识约 10,000 个模型小组件，用作 S3M 对象 ID。
- 多个 `ComponentId` 可以共享同一个 `DeviceId`，用于把小组件聚合成可查询设备。
- Web 端点击任一组件后，应先读取 `DeviceId`，再查询并高亮同一设备的全部组件。
- 出入口、泄漏源和道路目前是候选字段，不代表最终人工确认点位；不得把候选组件直接当作精确门、法兰或道路中心线。

## 遇到的问题与解决方案

### 通用投影转换后模型记录为空

原因：通用 `CoordSysTranslator` 不支持直接转换模型数据集的几何表达。

解决：保留模型局部米制网格，以模型锚点完成 4547 到 4490 的转换，并设置经纬度定位语义；先用单对象数据源验证，再执行全量 10,358 条转换。

### 生成瓦片时内存风险

原因：模型数据集约 1 GB，场景同时打开时会额外占用显存和内存。

解决：保存工作空间后接受 iDesktopX 的“关闭场景生成瓦片”建议，线程数由 16 降到 8，瓦片生成过程中不打开场景。

### 小组件与设备查询粒度冲突

原因：`DeviceId` 允许多个组件组成一个设备，因此不适合作为瓦片对象唯一 ID。

解决：使用唯一的 `ComponentId` 作为瓦片对象 ID，同时将 `DeviceId` 等聚合字段写入属性 DB。前端以 `ComponentId` 选中，以 `DeviceId` 聚合查询。

### Web 端与 iDesktop 材质色彩不同

原因：除了纹理压缩，Web 端环境光、太阳光、HDR、色调映射、曝光、Gamma 和后处理都会改变最终颜色。

解决：本次缓存保留高分辨率纹理、法线和普通材质，不强行把普通材质转换为 PBR。后续在同一测试相机和同一时间条件下校准 Web 渲染参数。
