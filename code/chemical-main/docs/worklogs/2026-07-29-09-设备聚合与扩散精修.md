# 设备聚合与扩散精修阶段日志

## 阶段目标

- 保持本地 EPSG:4490 三维主场景可打开，不重启 iServer。
- 将三维拾取从“单个小组件”提升为“设备级查询”。
- 优化体扩散的空间落点、顺风覆盖和非球形体云。
- 缩短本地演示的首轮算法等待时间。

## 问题与根因

1. 已发布 S3M 属性只有 `SmID、ModelName、SmMaxZ、SmMinZ、包围盒`，没有 `EquipmentID/ParentID`，因此 SDK 只能返回单组件。
2. 本地 `Park_S3MObjectFootprint_2D.geojson` 有 10286 条模型足迹；核对 6 个泄漏源后确认其记录顺序与模型 SmID 一一对应，可作为当前设备聚合索引。
3. 体元原先只按浓度 Top-N 取样，结果集中在泄漏源附近，视觉上容易收缩成球。
4. 算法体元没有剔除明显逆风采样点，且顺风/横风距离没有完整传到渲染端。
5. 本地默认 96 帧在旧算法进程下长时间处于“生成中”；旧 8000 进程又未热重载新 Python 代码。
6. 8000 使用带密钥的备份环境启动时，前端未携带密钥会返回 401；本地演示必须显式关闭鉴权并绑定 `127.0.0.1`。

## 本阶段解决方案

- 新建设备空间聚合逻辑：
  - 支持按 ModelName 或 SmID 查设备。
  - 优先把管件/结构件吸附到 8m 内最近的 `TANK/EQUIPMENT` 主体。
  - 依据主体包围盒和相邻距离聚合组件，限制单设备最多 160 个组件。
  - 输出稳定 `EQ-{主模型名}`、主 SmID、当前组件 SmID、组件 SmID 列表、设备类型和设备包围盒。
- 三维拾取先立即返回原对象，再异步升级为设备级对象；设备组件使用 `setObjsColor/removeObjsColor` 整组高亮。
- 大屏设备信息面板显示设备编号、类型、聚合组件数、当前组件和关联传感器。
- 泄漏源选择支持从所属设备的任一聚合组件解析到已登记泄漏部件，算法源仍使用已校验的 4490/ENU 锚点。
- 扩散体元采用“58% 高浓度核心 + 顺风距离/横风侧向分箱覆盖”，剔除超出源区容差的逆风点。
- 输出 `alongWindDistanceMeters、crossWindDistanceMeters、sourceDistanceMeters`，并在前端按顺风覆盖保留远端羽流。
- 渲染体元强制保持长轴沿风、横轴收窄、竖轴压缩，降低透明度并保留体积围栏。
- 本地默认改为 48 帧、5 秒步长，仍覆盖约 4 分钟事故演化。
- 仅重启本地 8000 算法服务加载新代码，未重启 8090 iServer。
- 生产构建尝试后原 Vite 进程退出，已单独恢复 5173；最终 5173、8000、8090 均重新健康。

## 回滚

- 设备聚合：移除拾取后的设备 enrichment，原始 SmID/ModelName 拾取仍可使用。
- 设备高亮：关闭 `highlightEquipmentAssembly` 调用，不影响场景加载。
- 扩散采样：恢复原 `heapq.nlargest` 单一 Top-N 选择即可。
- 演示帧数：把 `PHASE1_DEFAULT_SCENARIO.frameCount/frameStepSec` 恢复为 `96/4`。
- 算法服务：停止当前 8000 进程并用原启动参数恢复；无需改动 iServer。

## 收获与后续

- 当前设备聚合是发布字段缺失时的可运行适配层，正式交付仍应在 UDBX/S3M 中增加 `EquipmentID`，由数据治理层给出权威组件清单。
- 精度继续提升需要真实泄漏实验或 CFD/现场标定数据；当前优化解决空间约束、取样偏置和展示语义，不虚构实验精度。
- 下一阶段再做 Primitive 实例化、设备拓扑编辑器、喷口法向和材质重发布，避免在汇报前扩大风险。
