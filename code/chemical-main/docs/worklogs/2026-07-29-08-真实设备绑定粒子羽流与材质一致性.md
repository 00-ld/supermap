# 真实设备绑定、粒子羽流与材质一致性阶段记录

日期：2026-07-29  
运行方式：本地运行；本阶段未部署项目到远程服务器

## 阶段目标

1. 纠正此前仅靠硬编码坐标、但没有落到真实模型对象的出入口和泄漏源。
2. 把单个球体扩散改为受风场和气体物性控制的有界粒子羽流。
3. 恢复本地算法服务，使 `/screen` 可以真实调用 8000 端口算法。
4. 在不改动 iServer 原始缓存的前提下，减少 Web 端对模型材质和色彩的二次偏移。

## 发现的问题与根因

### 1. 旧绑定的 SmID 与模型名称不一致

从本地 iServer 数据服务和 `Park_S3MObjectFootprint_2D.geojson` 交叉核验后发现，旧配置中的部分 SmID 实际对应其他建筑或储罐。例如 SmID 182、452、2049、7302 并不是配置声称的目标对象；SmID 8751 虽然确实是 `PIPE_709`，旧经纬度也没有落入它的发布轮廓。

根因是之前只校验“坐标在园区范围内”，没有校验：

- SmID 是否存在；
- `ModelName` 是否与 SmID 一致；
- 4490 锚点经受控 4547 适配后是否位于该模型对象的发布轮廓内；
- 一个业务 ID 是否重复绑定到多个模型对象。

### 2. 球状体云缺少真实扩散形态

旧体云以少量大椭球表达整个浓度网格，基础半径直接受 20 米网格控制，视觉上仍接近“多个气球”。气体浮升、密度、湍流、沿风向和横风向尺度没有形成足够明显的差异。

### 3. 算法按钮失败不是算法本体故障

8000 端口原算法进程已经退出；首次恢复时又发现 `.env.local` 不是 UTF-8，Uvicorn 的 `--env-file` 读取失败。使用仓库已有 `.env.local.utf8.bak` 后服务可以启动，但旧 Vite 进程仍保存旧密钥，因此代理返回 401。

处理方式：

- 不重启 iServer、Java 后端或其他 Java 进程；
- 只启动本地 8000 算法服务；
- 确认 5173 监听进程确实是本项目 Vite 后，只替换该单一进程；
- 验证 `/screen`、算法直连和 Vite 算法代理均返回 200。

### 4. iServer 与 Web 材质差异不能全部靠前端修复

本地 S3M 配置显示：

- `associateMaterialFile` 为空；
- 材质类型为 `Normal`；
- 纹理使用 `CRN_DXT5`；
- 开启三层 Texture LOD，简化比例为 0.75 / 0.5 / 0.25；
- 第二纹理为 `ShadowMap`。

这意味着 Web 端可以消除额外 gamma、CSS 滤镜和过早粗 LOD，但无法从缺失的关联材质文件中恢复 iDesktop 原材质。若仍要求高度一致，必须在 iDesktopX 中按 WebGL/S3M 目标重新生成缓存并保留材质、纹理色彩空间和必要贴图。

## 实施结果

### 统一绑定

建立并校验以下稳定绑定：

- 4 个厂房出入口：`EntranceID + SmID + ModelName + 4490 + ENU + roadNodeId`；
- 6 个设备泄漏源：
  - SmID 355 / `PIPE_089`
  - SmID 366 / `EQUIPMENT_0317`
  - SmID 351 / `TANK_059`
  - SmID 151 / `PIPE_040`
  - SmID 145 / `EQUIPMENT_0296`
  - SmID 8751 / `PIPE_709`

每个泄漏源携带：

- `leakSourceId`
- `facilityId`
- `modelObjectId`
- `modelDataset`
- `modelSmId`
- `modelName`
- `equipmentType`
- `bindingRole`
- `bindingMethod`
- `gasCode`
- `supportedGasCodes`
- `sourceShape=VOLUME`
- EPSG:4490 点、局部 ENU 点和体渲染范围

场景拾取结果也会返回同一组绑定字段，避免传感器、扩散、溯源和路径规划各维护一套坐标。

### 粒子羽流

- CO、NH3、CH4、O2 分别具有独立的速度、浮升、密度、沿风向尺度、横风向尺度、竖向尺度和湍流参数。
- 平面浓度单元转换为多个确定性小粒子，不再用单个大球表达。
- 粒子沿风向拉伸、横风向扰动、竖向浮升或沉降。
- 粒子年龄使用沿风投影距离和释放高度有效风速计算；实测 `sigw` 存在时，竖向宽度使用与浓度场一致的拉格朗日时间尺度。
- 粒子数量按当前帧绝对浓度归一化，不再让 1 ppm 和 1000 ppm 生成相同数量。
- 单帧最多渲染 72 个体元，每个体元 2–5 个粒子；响应级粒子预算也有显式上限，避免浏览器持续增长。
- 三维相机改为侧风观察位，同时看见设备泄漏口和下风羽流；所有相机偏移使用局部 ENU 米制计算。
- 泄漏点和粒子均受对应设备的 `volumeFence` 限制。

### 材质显示

- 场景 gamma 恢复为 1；
- 去掉 Canvas 的 brightness / contrast / saturation 二次滤镜；
- S3M `lodRangeScale` 从 2 降为 1.25，减少近景过早切到粗糙纹理。

这些修改只减少 Web 端二次失真，不覆盖 iServer 缓存材质。

## 回滚方法

1. 关闭三维扩散功能开关，可保留二维算法结果而不创建粒子实体。
2. 将 `VOLUMETRIC_DIFFUSION_CELL_LIMIT` 设为 0 或恢复旧实体渲染分支，可快速停用新羽流。
3. 恢复 `spatial-assets.4490.json` 前一版本即可回退本阶段的出入口和设备源绑定；不需要修改 iServer 原始数据。
4. 材质调整只涉及前端 gamma、Canvas filter 和 `lodRangeScale`，可逐项恢复。
5. 本阶段没有修改、删除或覆盖 UDBX、S3M 缓存和远端服务。

## 阶段收获

- 工业三维绑定必须同时校验业务 ID、模型 SmID、模型名称、CRS 和空间包含关系，单独验证经纬度范围没有意义。
- “模型对象中心”适合建立数据关联，但设备泄漏可视化还需要考虑外表面、遮挡和侧风观察视角。
- 真实体扩散不是把球拉长，而是用有界、稀疏、受气体物性和风场控制的小粒子簇表达概率和浓度。
- 材质一致性首先取决于缓存发布质量；前端调色只能消除二次失真，不能补回未发布材质。
