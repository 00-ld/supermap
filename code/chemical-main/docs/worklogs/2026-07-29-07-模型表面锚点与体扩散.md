# 2026-07-29 模型表面锚点与体扩散

## 阶段目标

- 将出入口从旧估算坐标改为厂房模型表面绑定。
- 将泄漏源绑定到油管模型对象，气体从该点开始扩散。
- 将线状风险柱改为三维体扩散，并限制在园区模型空间内。
- 保持 `/screen`、本地 iServer 主场景和现有算法接口可运行。

## 问题与根因

1. 出入口和泄漏源仍通过旧 LOCALMAP → 经纬度近似转换放置，未使用已发布 S3M 模型的真实拾取位置。
2. 旧渲染器显式创建了从地面到高空的 `polyline` 风险柱，并绘制风向连接线，所以结果表现为线而不是气体体积。
3. 算法只返回二维 `cells`，前端只能自行猜测高度，无法表达真实的竖向扩散结构。
4. 初版整改仍在每个入口保存了一份旧局部分析点，路径终点与新的 4490/ENU 模型锚点不一致；初版体元的 `zMeters` 又同时被算法和前端当作绝对/相对高度，造成重复抬高。

## 解决方案

- 在本地 `huangong_4490` 场景中直接拾取模型表面：
  - 油管泄漏点：`SmID=8751`，`113.536887E, 34.819087N, H=8.4m`。
  - 四个厂房门采用地面拾取点，并绑定相邻厂房 `SmID=182/7302/2049/452`。
- 空间资产状态使用 `MODEL_SURFACE_BOUND`，与 `PUBLISHED` 一起视为可用于相机定位和路径终点的已校核位置。
- 删除入口和泄漏源上的第二套手填分析坐标，新增唯一的 `analysisFrameLocalMeters` 适配器；路径终点统一由模型 ENU 锚点派生，门标记、相机和规划终点共用同一 `EntranceID`。
- 默认泄漏源调整为“中部管廊法兰”，算法请求携带 `leakSourceId + gasCode + gasId + sourceShape + point4490 + modelObjectId`；算法拒绝 `gasCode/gasId` 冲突。
- 扩散算法每帧新增 `volumeCells`，每个体元包含 `x/y/zOffsetMeters/radiusMeters/concentration`；`zMeters` 仅保留为兼容字段，响应新增 `releaseGeometry.shape=VOLUME`。
- 前端以油管 4490 锚点为 ENU 原点，将算法平面位移转换到三维 ECEF；算法 Y 轴向南，转换时显式反转到 ENU north。
- 删除风险柱、风向线和平面扩散圈，只渲染半透明球形体元。
- 体扩散限制为水平半径 320 米、相对高度 -2–85 米；球体半径也计入围栏，越界体元直接丢弃，贴边体元缩小，不再把越界结果钳回边界。
- 每个响应最多返回 4800 个可视化体元；候选单元先按围栏过滤，再用有界 Top-K 选择，避免对大网格全量排序；拒绝 NaN/Infinity 和非对象 `volumeFence`，防止异常输入拖垮本地服务。
- 出入口相机使用局部 ENU 米制偏移、34° FOV 和 130–140 米近景距离，避免旧经纬度偏移与广角畸变。

## 验证证据

- 空间契约校验：7 个场景、4 个厂房出入口、1 个体泄漏源通过。
- 算法 HTTP 实测：`shape=VOLUME`、`visualizationOnly=true`、2 帧共 42 个体元，气体绑定为 `ch4`。
- 浏览器实测：点击“扩散模拟”成功生成 96 帧动画；体云从油管模型内部出现，未出现黑色连接线或竖直风险柱。
- 路径无危险场回归：四个由 ENU 派生的入口均可参与规划，返回 `park-north`、4 个路径点和 4 条候选路线；实时最终扩散帧下仍会因危险浓度遮罩提示“未找到可用逃生路径”，属于安全约束而非坐标失配。

## 收获与后续

- 发布服务不一定必须新增点数据集才能先完成绑定；稳定的 `SmID + EPSG:4490 拾取点` 可以作为本地整改阶段的模型表面契约。正式交付时仍建议在 iDesktopX 中将同一字段固化为独立点数据集。
- 二维算法可以继续在局部米制平面运行，但三维结果必须以注册模型锚点为原点做 ENU 转换，不能再把整套旧 LOCALMAP 直接映射到经纬度。
- 最终扩散帧可能把所有可用道路判为危险，从而正确拒绝生成路径；验收坐标绑定时必须另用空危险场回归，不能用“强行返回一条路线”掩盖安全约束。

## 回滚

- 将 `frontend/src/config/spatial-assets.4490.json` 中绑定状态改回 `UNVERIFIED` 可立即阻止出入口用于路径和相机。
- 恢复 `drawDiffusionOverlayEntities` 的旧分支可回到平面/风险柱展示，但不建议继续使用。
- 算法消费者可忽略新增 `volumeCells` 和 `releaseGeometry`；原有二维 `cells` 字段保持兼容。
