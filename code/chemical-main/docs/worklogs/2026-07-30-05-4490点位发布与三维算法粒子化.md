## 遇到的问题与解决方案

### iServer 重启脚本指向错误 Tomcat

系统环境中的 `CATALINA_HOME` 指向另一套 Tomcat，前两次关闭命令没有影响 8090。
处理时先按监听端口核验进程路径，再停止精确 PID，清除当前进程继承的 Catalina 变量，
由 2026 iServer 目录启动。旧服务始终保持可恢复。

### 算法服务重启后页面鉴权不一致

算法服务与 Vite 代理最初继承了不同的启动环境，页面请求返回密钥错误。处理时未输出密钥，
让 8000 和 5173 两个精确进程共同继承根目录 `.env.local` 后分别重启。

### 粒子滤波收到重复空间位置

监控目录存在不同传感器 ID 共用同一算法落点的情况。后端继续严格拒绝重复点，防止统计偏置；
前端构造算法输入时按六位小数坐标去重，优先保留浓度最高的观测。

### 热更新期间出现一次材质推断错误

Vite 热更新恰好发生在旧场景清图和新 KDE 面创建之间，旧 Viewer 被销毁。全量重新加载后未复现；
最终验证清除算法图层后恢复为 414 个基础实体，页面没有材质错误。演示前不再对三维组件做热更新。

## 回滚

- 恢复
  `G:\竞赛\超图杯\workspace-processing\iserver-services.before-huagong-finally-4490.xml`
  到 2026 iServer 的 `WEB-INF\iserver-services.xml`，再按精确进程路径重启，可撤销新发布服务。
- 将场景清单主 URL 恢复为旧服务即可回退前端场景，新服务和旧服务互不覆盖。
- 关闭 `VITE_FEATURE_INVERSION_KDE_3D` 可仅回退粒子/KDE 三维层，保留估计点。
- 删除派生发布工作空间不会影响原始 `huagong.smwu`、UDBX 或 S3M 缓存。

## 收获

工业三维算法的“上三维”不能只把二维结果贴到模型上。扩散需要明确的垂直分布、浮升、
湍流和体积边界；溯源需要把后验样本、概率密度和置信范围区分表达。同时，进入算法的多个
传感器必须拥有独立空间信息，否则增加 ID 数量并不会增加有效观测信息。
