# B 套模型绑定点位算法迁移工作日志（F11，2026-08-01）

## 背景与问题

三维场景中存在两套监控点位：

- **A 套（算法点位，已删除）**：前端 `REAL_SENSOR_LAYOUT`（81 点）+ `SUPPORT_MONITORING_SENSOR_SEEDS`（29 点），坐标基于 DOM 底图系（local 0~1587 × 0~947，A 锚点 113.535771/34.818673）。参与扩散采样与溯源观测。
- **B 套（模型绑定点位，算法数据源切换目标）**：iServer `MonitorPoints_4490`（1072 点，导出 `DevicePoint_2D.geojson`），Wgs84 经纬高 + `ModelName` 字段绑定三维模型对象，点击模型查询走 ModelName（`devicePointQuery.ts`）。只做三维模型挂点查询，不参与算法。

**根因发现**：A 套点位（基于 DOM 底图）与三维模型真实位置存在约 300~1000m 系统性错位。B 套 887 个气体点位换算到 A 锚点 ENU 后分布在 east∈[-65.7, 878.6]、north∈[-83.2, 403.1]——模型真实位置在 A 锚点以北为主，而旧算法网格（0~1587 × 0~947，y 向南）只覆盖模型南侧，**仅 150/887 落进网格**。这就是"A 套点位跑出模型"的根源。

## 决策（用户确认）

1. A 套前端+后端全删（realSensorLayout / SUPPORT_MONITORING_SENSOR_SEEDS / sensor 表 / sensor_reading / monitor_point / SSE 链）。
2. 扩散泄漏源改用 `spatial-assets.4490.json` 已配准的 6 个模型系泄漏源锚点（modelLocalEnuMeters，与 B 套点位同一 ENU 基准）。
3. 2D 底图/设施标注本次不动（保留旧系，仅 2D 小地图视口切算法系）。

## 算法坐标系（ALGORITHM_FRAME）

```
X = east + 80        east = (lon - 113.535771) × 111320 × cos(34.818673°)
Y = -north + 420     north = (lat - 34.818673) × 111320
网格：1000 × 540（gridSize 20，mapMetersPerUnit 1）
```

- B 套 887 个气体点位 → 高低位同坐标去重保留低位 → **583 个唯一位置**，算法系 x∈[14, 959]、y∈[17, 503]，全部落网格。
- 泄漏源（6 个）→ 算法系 X≈35~86、Y≈71~352，全部落网格。
- B 套点位三维显示仍按 Wgs84 原值放置（**零偏差**，模型绑定不破坏）；算法 overlay 经 `algorithmToLocal` 逆变换回模型位置。
