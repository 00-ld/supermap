# 化工园区移动端 App + 后端 task 任务指派模块 设计方案

> 本方案是移动端工程与后端 task 模块的权威设计文档，与 `超图集成记录.md`（超图技术细节）互补。
> 落盘于移动端工作目录 `G:\竞赛\超图杯\移动端\`，遵守"移动端代码只在指定目录生成、不污染网页端"约束。

---

## 一、背景与目标

### 1.1 业务缺口
超图杯化工园区项目已有完整网页端（Vue3 + Spring Boot + FastAPI 算法 + SuperMap iServer/iClient3D），覆盖"感知-模拟-溯源-决策-三维表达"闭环。但**现场处置环节缺失**：事故发生后，指挥员无法把任务指派给巡检小车或工作人员，现场人员无法在移动端打卡拍照确认异常解除。

### 1.2 目标
从零开发 **SuperMap iMobile 2026 原生 Android App**，承载三大业务闭环：
> 某处发生事故 → 指派巡检小车或工作人员到指定位置 → 现场打卡拍照检测异常 → 成功打卡后异常解除。

同时在现有后端新增 `task` 任务指派模块作为业务后盾。

### 1.3 为什么用 iMobile 原生而非 H5/PWA
原规划文档写"短期 H5/PWA，长期 iMobile"，本次升级为直接做 iMobile 原生端：
- 突出 SuperMap 移动 GIS 能力（竞赛核心评分点）
- 离线/弱网现场可用（许可本地化、地图可缓存）
- 原生相机/GPS 调用更稳定

## 四、后端 task 模块设计

### 4.1 task 表 DDL

**迁移脚本**：`db/migrations/005_add_task_table.sql`（同步追加到 `deploy/mysql/init.sql`，更新 `db/migrations/README.md`）

一张 `task` 表贯穿全闭环，状态用 `status` 枚举字符串，关联 warning_history/patrol_car/employee，打卡数据落同表。

```sql
CREATE TABLE IF NOT EXISTS `task` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    `title` VARCHAR(200) NOT NULL COMMENT '任务标题',
    `description` VARCHAR(1000) DEFAULT NULL COMMENT '任务描述',
    `type` VARCHAR(20) NOT NULL DEFAULT 'incident' COMMENT '任务类型：incident事故/patrol巡检/drill演练',
    `status` VARCHAR(20) NOT NULL DEFAULT 'pending' COMMENT '状态：pending待指派/assigned已指派/processing处置中/pending_review待验收/completed已完成/canceled已取消',

    -- 事故来源
    `warning_history_id` INT DEFAULT NULL COMMENT '关联告警历史ID',
    `gas_type` VARCHAR(20) DEFAULT NULL COMMENT '气体类型（冗余自告警）',

    -- 指派目标
    `assignee_type` VARCHAR(10) DEFAULT NULL COMMENT '指派对象：car/employee',
    `car_id` INT DEFAULT NULL COMMENT '指派巡检车ID',
    `employee_id` BIGINT DEFAULT NULL COMMENT '指派员工ID',

    -- 目标位置
    `x` DOUBLE DEFAULT NULL COMMENT '目标X坐标（园区本地米制）',
    `y` DOUBLE DEFAULT NULL COMMENT '目标Y坐标',
    `area_name` VARCHAR(100) DEFAULT NULL COMMENT '区域名称',

    -- 指派/接单
    `creator_user_id` BIGINT DEFAULT NULL COMMENT '创建人用户ID',
    `assigned_time` DATETIME DEFAULT NULL COMMENT '指派时间',
    `accepted_time` DATETIME DEFAULT NULL COMMENT '接单时间',

    -- 现场打卡
    `checkin_time` DATETIME DEFAULT NULL COMMENT '打卡时间',
    `checkin_x` DOUBLE DEFAULT NULL COMMENT '打卡经度（WGS84）',
    `checkin_y` DOUBLE DEFAULT NULL COMMENT '打卡纬度（WGS84）',
    `checkin_photo_base64` LONGTEXT DEFAULT NULL COMMENT '打卡照片base64（与inspect_record.image_base64同类型）',
    `yolo_person_count` INT DEFAULT NULL COMMENT 'YOLO识别人数（算法不可用时为空）',
    `checkin_remark` VARCHAR(500) DEFAULT NULL COMMENT '打卡备注',

    -- 验收
    `review_result` VARCHAR(20) DEFAULT NULL COMMENT '验收结果：pass/reject',
    `review_remark` VARCHAR(500) DEFAULT NULL COMMENT '验收备注',
    `review_time` DATETIME DEFAULT NULL COMMENT '验收时间',
    `reviewer_user_id` BIGINT DEFAULT NULL COMMENT '验收人用户ID',

    -- 异常解除
    `warning_resolved` TINYINT NOT NULL DEFAULT 0 COMMENT '异常解除幂等标志：0未解除/1已解除',
    `inspect_record_id` BIGINT DEFAULT NULL COMMENT '关联巡检记录ID（预留，首版不写）',
    `source` VARCHAR(32) NOT NULL DEFAULT 'mobile' COMMENT '任务来源：mobile/web',

    `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    PRIMARY KEY (`id`),
    KEY `idx_task_status` (`status`),
    KEY `idx_task_warning` (`warning_history_id`),
    KEY `idx_task_car` (`car_id`),
    KEY `idx_task_employee` (`employee_id`),
    KEY `idx_task_creator` (`creator_user_id`),
    KEY `idx_task_created` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务指派表（巡检/事故处置闭环）';
```

关联列允许 NULL，**不加 FK 约束**（与既有 warning_history/patrol_car 一致）。`warning_resolved` 幂等标志：验收通过且 warning_history_id 非空时 service 检查此标志，未解除才执行复位。

### 4.2 POJO / DTO

**POJO**（`com.at.pojo.Task`）：`@Data`，LocalDateTime 时间，字段对齐表。

**DTO**（`com.at.pojo.dto`）：
- `TaskCreateDTO`：title@NotBlank, type@Pattern(incident|patrol|drill), warningHistoryId, gasType, assigneeType@Pattern(car|employee), carId, employeeId, x, y, areaName, description
- `TaskAssignDTO`：taskId@NotNull, assigneeType, carId, employeeId
- `TaskCheckinDTO`：taskId@NotNull, checkinX, checkinY, checkinRemark（照片走 multipart，不在此 DTO）
- `TaskReviewDTO`：taskId@NotNull, reviewResult@Pattern(pass|reject), reviewRemark
- `TaskQueryDTO`：status, assigneeType, carId, employeeId, warningHistoryId, keyword
- `TaskResponseDTO`：含 `fromEntity(Task)` 静态工厂
- 接单/取消复用既有 `IntIdDTO`

### 4.3 Mapper（`com.at.mapper.TaskMapper` + `resources/mapper/TaskMapper.xml`）

```java
int insert(Task task);                                     // useGeneratedKeys 回填 id
int updateById(Task task);
Task selectById(Long id);
List<Task> selectByQuery(TaskQueryDTO query);              // 动态 <where>/<if>
List<Task> selectByAssignee(String assigneeType, Long employeeId, Integer carId);
int updateStatus(@Param("id") Long id, @Param("fromStatus") String from, @Param("toStatus") String to);  // CAS 原语
int updateCheckin(Task task);                              // 写 checkin_* + yolo_person_count
int updateReview(Task task);                              // 写 review_* + warning_resolved
```

`updateStatus` 是核心状态机原语：
```sql
UPDATE task SET status=#{toStatus} WHERE id=#{id} AND status=#{fromStatus}
```
返回行数判并发竞争，行数=0 抛 `ApiException(409,"任务状态已变更，请刷新")`。

### 4.4 Service（`com.at.service.TaskService` + `com.at.service.impl.TaskServiceImpl`）

所有状态转移走 `updateStatus` CAS，行数=0 抛 409：

| 方法 | 状态转移 | 副作用 |
|---|---|---|
| `createTask(TaskCreateDTO, Long creatorUserId)` | (带指派)→assigned / (无指派)→pending | 带 warningHistoryId 则校验存在并冗余 gasType/x/y/areaName |
| `assignTask(TaskAssignDTO)` | pending→assigned | 写 assigned_time |
| `acceptTask(Long taskId, Long currentUserId)` | assigned→processing | 写 accepted_time |
| `checkin(TaskCheckinDTO, MultipartFile photo, Long currentUserId)` | processing→pending_review | 写 checkin_*；调 `ImageAnalysisService.analyzePerson(photo)` 拿 personCount+image_base64；**算法不可用捕获降级**：照片照存，yolo_person_count 空，不阻塞 |
| `reviewTask(TaskReviewDTO, Long reviewerUserId)` | pass:→completed / reject:→processing | pass 且 warning_history_id 非空且 warning_resolved=0 → resolveWarning |
| `cancelTask(Long taskId)` | pending/assigned→canceled | — |
| `getTaskDetail/listTasks/myTasks` | — | 查询 |

`private resolveWarning(Task task)`：`CarMapper.resetStatus(carId)` + `task.warning_resolved=1`（幂等，先查标志再复位）。

### 4.5 Controller（`com.at.controller.TaskController`，`@RequestMapping("/api/task")`）

| 方法 | 路径 | 鉴权 | 入参 | 返回 |
|---|---|---|---|---|
| POST | `/api/task` | @RequiresRole("admin") | TaskCreateDTO | Result<TaskResponseDTO> |
| POST | `/api/task/assign` | @RequiresRole("admin") | TaskAssignDTO | Result<?> |
| POST | `/api/task/accept` | 登录即可 | IntIdDTO | Result<?> |
| POST | `/api/task/checkin` | 登录即可 | taskId/checkinX/Y/remark(form) + MultipartFile photo | Result<TaskResponseDTO> |
| POST | `/api/task/review` | @RequiresRole("admin") | TaskReviewDTO | Result<?> |
| POST | `/api/task/cancel` | @RequiresRole("admin") | IntIdDTO | Result<?> |
| GET | `/api/task/list` | 登录即可 | TaskQueryDTO(query) | Result<List<TaskResponseDTO>> |
| GET | `/api/task/{id}` | 登录即可 | @PathVariable Long id | Result<TaskResponseDTO> |
| GET | `/api/task/my` | 登录即可 | assigneeType/carId/employeeId | Result<List<TaskResponseDTO>> |

`creatorUserId`/`reviewerUserId`/`acceptUserId` 用 `@RequestAttribute(value="userId", required=false) Long userId`（TokenInterceptor 已把 claims.id 写入 request attribute）。

**安全说明**：employee 表当前无 user 关联，首版 `assignee_type=car` 任何登录用户可代车打卡；`assignee_type=employee` 无映射则放行并留 TODO（后续给 employee 加 user_id 列做强校验，见待确认项）。

### 4.6 打卡 YOLO 复用决策

复用 `ImageAnalysisService.analyzePerson`，但不直接调既有 `/api/analysis/person`（admin 限定 + 默认 location）。`TaskService.checkin` 内 `@Resource` 注入 `ImageAnalysisService` 编程式调用：
- count → `task.yolo_person_count`
- image_base64 → `task.checkin_photo_base64`
- 首版不关联 inspect_record_id（零改动既有稳定 service）；inspect_record 仍由 analyzePerson 副作用产生
- `analysis.service.url` 未配置时 analyzePerson 抛 503，checkin 捕获降级，不阻塞闭环

### 5.2 网络层（Retrofit + OkHttp + Gson，已实现）

- `HttpClient.java`：OkHttpClient 加 `TokenInterceptor`——每请求注入 Header `token: <SessionManager.token>`（Header 名是 `token`，与网页端一致）；连接超时 15s，读超时 30s（打卡图片慢）；`HttpLoggingInterceptor`(debug BODY)；Gson 转换器
- `ApiService.java`（P0 只放 login + getAllCars + listWarnings，P1 补全 task 全套）：

```java
@POST("api/auth/login") Call<ApiResult<String>> login(@Body LoginRequest body);
@GET("api/car/getAllCars") Call<ApiResult<List<CarVO>>> getAllCars();
@GET("api/history/list") Call<ApiResult<List<WarningVO>>> listWarnings();
// P1 追加：
@GET("api/task/list") Call<ApiResult<List<TaskVO>>> listTasks(@Query("status") String status);
@GET("api/task/{id}") Call<ApiResult<TaskVO>> getTask(@Path("id") long id);
@POST("api/task") Call<ApiResult<TaskVO>> createTask(@Body TaskCreateDTO dto);
@POST("api/task/assign") Call<ApiResult<Void>> assign(@Body TaskAssignDTO dto);
@POST("api/task/accept") Call<ApiResult<Void>> accept(@Body IntIdDTO dto);
@Multipart @POST("api/task/checkin") Call<ApiResult<TaskVO>> checkin(
    @Part("taskId") RequestBody id, @Part("checkinX") RequestBody x,
    @Part("checkinY") RequestBody y, @Part("checkinRemark") RequestBody r,
    @Part MultipartBody.Part photo);
@POST("api/task/review") Call<ApiResult<Void>> review(@Body TaskReviewDTO dto);
@POST("api/task/cancel") Call<ApiResult<Void>> cancel(@Body IntIdDTO dto);
@GET("api/employee/list") Call<ApiResult<List<EmployeeVO>>> getEmployees();
```

- Result 拆包：`ApiResult<T>`（{code,message,data,ok,timestamp,requestId}），`isSuccess()` 检查 ok && code==200；401 清 token 跳登录页
- baseUrl：`AppConfig` 从 `assets/config.properties` 读 `backend.baseurl`（开发机局域网 IP，**不写 localhost**）和 `iserver.baseurl`

### 5.3 iMobile MapView 加载 iServer REST 地图（已实现，见 `SuperMapHelper.java`）

**超图集成点 2**：用 `EngineType.Rest` 打开 iServer 标准 REST Map（非 OpenGLCache，非废弃的 mapoverlay 方案）。

```java
DatasourceConnectionInfo info = new DatasourceConnectionInfo();
info.setEngineType(EngineType.Rest);
info.setServer(config.getMapUrl());   // .../rest/maps/建筑单体校核图_CGCS2000
Datasource ds = workspace.getDatasources().open(info);
map.getLayers().add(ds.getDatasets().get(0), true);
map.viewEntire();   // 自适应数据范围，不硬编码 setViewBounds
map.refresh();
```

线程模型：数据源打开是网络 IO 放工作线程；图层添加/范围设置/刷新回主线程（`mapView.post`），因 iMobile Map 状态非线程安全。资源释放顺序：map.close → workspace.dispose → mapControl.dispose。

## 六、业务流程串联（事故→指派→打卡→解除 完整时序）

```
[1] 事故发生
    A: 巡检车告警 → patrol_car.warning=1 + warning_history 写入（既有 setWarning/add）
    B: 人工上报（移动端/网页端 admin）
    ↓
[2] 管理员移动端创建处置任务
    POST /api/task (TaskCreateDTO{warningHistoryId, gasType, x,y, assigneeType, carId/employeeId})
    createTask: 校验 warningHistoryId 存在并冗余字段；status=pending；带指派则→assigned
    ↓
[3] 指派（若创建时未指派）
    POST /api/task/assign (admin) → CAS pending→assigned, 写 assigned_time
    ↓
[4] 被指派人接单（到现场）
    POST /api/task/accept (登录即可) → CAS assigned→processing, 写 accepted_time
    ↓
[5] 现场打卡（定位+拍照）
    POST /api/task/checkin (multipart: taskId, checkinX/Y, remark, photo)
    checkin: CAS processing→pending_review；写 checkin_*；
      调 ImageAnalysisService.analyzePerson(photo)（算法在线时）:
        count→task.yolo_person_count, image_base64→task.checkin_photo_base64
      算法不可用→降级：照片照存，yolo_person_count 空，不阻塞
    ↓
[6] 管理员验收
    POST /api/task/review (admin, {reviewResult: pass|reject})
    pass: CAS pending_review→completed；写 review_*
          若 warning_history_id 非空 且 warning_resolved=0:
            → resolveWarning: CarMapper.resetStatus(carId)  // patrol_car.warning=0 复位
              task.warning_resolved=1（幂等）
    reject: CAS pending_review→processing（驳回重做，回 [4]/[5]）
    ↓
[7] 闭环完成
    patrol_car.warning 复位（异常解除），task.status=completed。
    地图层巡检车图标恢复正常色，任务点变已完成态。
```

状态机：
```
pending ──assign──> assigned ──accept──> processing ──checkin──> pending_review
   │                     │                     │                       │
   └──cancel──>canceled  └──cancel──>canceled  └──cancel──>canceled    │ review(pass)→completed
                                                                      │ review(reject)→processing(回退)
```
所有转移走 `updateStatus(id, from, to)` CAS 原语，并发安全。

## 七、关键风险与隔离保障

### 7.1 移动端工程不污染网页端
- 独立 Gradle 工程：`移动端/settings.gradle` 不 include 任何 chemical-main 路径。根 `G:\竞赛\超图杯\.git` 单仓库，`移动端/` 作子目录纳入版本控制但独立构建，不影响 backend Maven / frontend npm
- `移动端/.gitignore` 覆盖 Android 产物（build/、*.apk、local.properties、*.slm 等）
- 后端 task 模块增量加在 backend，不动 chemical-main 既有前端/算法文件（除 005 迁移 + init.sql 追加 + manifest/README 增量）

### 7.2 iMobile license
- `.slm` 放 `移动端/app/src/main/assets/License/`，App 启动从 assets 拷到 `/sdcard/SuperMap/License/`，再 `Environment.setLicensePath`+`initialization`
- `.slm` 不提交 git（`.gitignore` 加 `*.slm`）

### 7.3 iServer 在线服务网络可达性兜底
- iServer `https://www.chemgas.lab6119.xyz/iserver` 公网 nps，移动端 4G/5G/wifi 直连可达
- 兜底：MapActivity 加载 try/catch，失败显示"地图服务不可达"+"重试"按钮；任务/事故列表走后端 8081 不依赖 iServer，地图加载失败不影响业务闭环

### 7.4 坐标系一致性
- 后端 task.x/y 与 patrol_car/monitor_point 一致（园区本地米制）
- 移动端打卡 GPS 是 WGS84 经纬度。首版存 WGS84 经纬度到 checkin_x/y，地图层由 iMobile 自身坐标投影显示。若后端需本地系做距离判定，加 `CoordUtil.wgs84ToLocal`（移植网页端 `supermapGeoreference.js` A 锚点）。P2 优化项，P0/P1 不做距离判定
