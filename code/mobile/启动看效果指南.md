## 二、准备 Android 运行环境（二选一）

### 选项 1：Android 模拟器（无需真机）

> **架构关键**：iMobile SDK 只有 armeabi-v7a 的 .so，但其 log4j-core-2.12.4.jar 用了 MethodHandle.invoke，硬性要求 minSdk 26。而 Google 的 v7a 系统镜像只发布到 android-25（android-26+ 无 v7a 镜像）。死结的解法：用 **android-34 arm64-v8a 镜像**——Android arm64 原生兼容 32 位 v7a 执行（系统镜像含 32 位 linker），APK 的 abiFilters='armeabi-v7a' 装到 arm64 模拟器能正常跑。

**装 emulator + platform-tools + arm64 镜像**（sdkmanager 已就绪）：
```bash
SDK=/c/Users/colorful/AppData/Local/Android/Sdk
SDKMGR="$SDK/cmdline-tools/latest/bin/sdkmanager.bat"

# 装 emulator + platform-tools + android-34 arm64 镜像（约 3-4GB，要等）
echo "y" | "$SDKMGR" "emulator" "platform-tools" "system-images;android-34;google_apis;arm64-v8a"

# 建 AVD（arm64）
"$SDK/cmdline-tools/latest/bin/avdmanager.bat" create avd \
  -n chemical -k "system-images;android-34;google_apis;arm64-v8a" -d pixel

# 启动模拟器（内存紧时加 -memory 2048，首次启动 2-3 分钟）
"$SDK/emulator/emulator.exe" -avd chemical -no-snapshot-load -memory 2048
```
> **内存注意**：16GB 机器跑后端(512MB)+模拟器(2GB)+IDE 会吃紧，启动模拟器前关掉 IDE 和前端 dev server。看到 Android 桌面即就绪。

### 选项 2：真机（更快，渲染更准）

1. 手机开发者选项 → 开启 USB 调试
2. 数据线连电脑
3. `adb devices` 能看到设备即可
4. 真机要改 baseUrl：编辑 `移动端/app/src/main/assets/config.properties`，把
   `backend.baseurl=http://10.0.2.2:8081/` 改成
   `backend.baseurl=http://192.168.0.101:8081/`（本机局域网 IP，手机与电脑同 WiFi）
5. 改完重编：`cd 移动端 && ./gradlew.bat assembleDebug`

## 四、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录失败 401 | 后端没起或地址错 | 确认 8081 在跑，模拟器用 10.0.2.2，真机用 192.168.0.101 |
| 地图空白 | iServer 不可达或许可未激活 | 确认能访问 `https://www.chemgas.lab6119.xyz`；首次启动许可需联网激活 |
| task 接口 500 | 后端跑的是旧代码 | 用上面的 bat 重启后端 |
| 装不上 APK | 架构不匹配 | iMobile SDK 只要 v7a 但 minSdk 26 跑不了 android-25 镜像；必须用 android-34 arm64-v8a 镜像（arm64 兼容 v7a），不能用 v7a 镜像 |
| 内存又满了 | 后端+模拟器+IDE 同时跑吃紧 | 后端限 512MB，关掉 IDE 和前端 dev server |
