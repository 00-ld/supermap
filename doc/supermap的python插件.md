# 超图三维化工园区模型批量命名工作总结

## 一、整体工作概述

本次工作围绕化工园区三维模型的数据整理与语义化命名展开。

原始模型中的对象名称大多由建模软件或脚本自动生成，主要表现为：

- `BUILDING_*`
- `TANK_*`
- `PIPE_*`
- `EQUIPMENT_*`
- `GRP_REG_*`

这些名称只能表示对象类型和编号，无法直接体现真实业务含义。为便于后续三维查询、设备识别、空间分析、风险监测和系统展示，使用 SuperMap 桌面端与 Python 接口，对模型数据集中的 `ModelName` 字段进行了批量、严格、可校验的中文语义化命名。

## 四、脚本采用的核心技术规则

### 1. 严格完整匹配

所有脚本都通过完整字符串进行匹配：

```python
if current_name in TARGET_NAMES:
```

或：

```python
target_name = name_mapping.get(current_name)
```

不会采用：

- 模糊匹配；
- 包含匹配；
- 前缀匹配；
- 相似名称推测；
- 自动补齐编号；
- 自动扩大连续范围。

### 2. 保留缺号和跳号

用户提供的编号清单可能存在跳号，这些跳号被视为有意安排。脚本不会自动补全缺失编号。

### 3. 对输入清单进行数量校验

大型批量脚本会检查：

- 每组原名称数量；
- 所有组的总数量；
- 是否存在重复名称；
- 是否存在跨组重复；
- 是否存在同一个原名称映射到两个目标名称；
- 目标名称是否误加入原名称集合。

如果校验失败，脚本会直接停止，不修改数据。

### 4. 对同名对象进行安全检查

当多个模型记录具有完全相同的原名称时，脚本会先统计该名称在数据集中的实际数量。只有实际数量与用户提供的数量一致时才修改，否则跳过，防止误改其他同名对象。

### 5. 使用动态可编辑记录集

脚本通过：

```python
CursorType.DYNAMIC
```

打开可编辑记录集，并按照以下流程修改：

```text
读取 ModelName
      ↓
判断是否严格匹配
      ↓
recordset.edit()
      ↓
setFieldValue("ModelName", 新名称)
      ↓
recordset.update()
```

### 6. 输出完整运行结果

脚本执行后会输出：

- 扫描记录总数；
- 成功修改记录数；
- 修改失败记录数；
- 匹配到的不同原名称数；
- 未匹配到的原名称数；
- 每个目标名称修改数量；
- 成功修改明细；
- 未匹配名称清单；
- 修改失败名称清单。
