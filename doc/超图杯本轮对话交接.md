## 3. 对豆包计划的判断

豆包计划整体方向是“全套 SuperMap 生态重构”，包括 iDesktopX、iServer、iPortal、iObjects、iClient、移动端、PPT、视频、文档等。

本轮判断：

- 方向是对的，但太散。
- 项目不应该推倒重写。
- 真正要做的是：**把评委看得见、问得到的 GIS 层全部换成 SuperMap；保留已有扩散、溯源、疏散等算法优势。**

核心结论：

> 冲超图杯一等奖，评委第一眼要看到“这是 SuperMap 生态做出来的 GIS 应用”，不是一个普通 Vue 系统里嵌了一个 iPortal 页面。

## 4. SuperMap 化改造总策略

用户明确要求：

> 能换为 SuperMap 软件的都换成 SuperMap。

因此最终策略调整为：

```text
SuperMap-first：能 SuperMap 化的 GIS 能力全部 SuperMap 化；
业务后端和算法内核不硬换。
```

### 4.1 应该替换成 SuperMap 的部分

| 当前能力 | 建议替换为 | 原因 |
|---|---|---|
| 二维 Canvas 地图 | SuperMap iClient for JavaScript / iServer 地图服务 | 让二维地图成为超图服务消费端 |
| Three.js / 自建三维页面 | SuperMap iClient3D for Cesium/WebGL | 三维数字孪生必须成为主展示入口 |
| iPortal iframe 嵌入 | iPortal 管资源，前端用 iClient3D 原生加载 | iframe 像外链，原生加载更像自研 GIS 应用 |
| GeoJSON / JS 静态要素 | iDesktopX 制作数据集，iServer 发布 REST 服务 | 形成桌面制图-服务发布-Web调用完整链路 |
| 天地图瓦片直连 | 通过 SuperMap 服务或 iClient 图层接入 | 保留天地图，但纳入 SuperMap 图层体系 |
| 本地坐标换算 | SuperMap 坐标转换/服务端投影能力为主 | 测绘叙事更正规 |
| IDW、等值线展示 | iServer 空间分析/等值线等值面能力承接 | 把算法图变成 GIS 分析成果 |
| 缓冲区、高危区、疏散避让 | iServer 空间分析 + 当前 D* Lite 算法 | SuperMap 做空间表达，算法做应急决策 |
| 项目演示大屏 | iPortal + iClient3D 综合态势大屏 | 最符合超图杯观感 |
| 移动端 | H5 优先，iMobile 可作为加分项 | 不要一开始就做重客户端 |

### 4.2 不建议硬换的部分

- FastAPI 扩散、溯源、路径规划算法不要换。
- Spring Boot 后端不用整体换。
- YOLO 图像识别不用换。
- 这些属于项目创新能力，SuperMap 主要负责 GIS 底座、服务发布、空间表达和三维展示。

## 7. 先从哪里开始动刀

推荐顺序：

### 第一阶段：修通现有 SuperMap 大屏

目标：

- iPortal 大屏能匿名打开。
- 页面不再停留在“正在加载...”。
- 解决 `401` 权限问题。
- 解决 `502` 资源或反代问题。
- 让项目里的“数字园区”入口可稳定访问。

这是后续所有 SuperMap 化改造的地基。

### 第二阶段：用 iDesktopX 整理 GIS 数据

目标：

- 整理园区边界、企业地块、道路、传感器点位、风险区。
- 将公开 OSM/天地图/现有坐标数据转为可发布数据集。
- 形成可解释的数据生产链路。

### 第三阶段：用 iServer 发布服务

目标：

- 发布地图服务。
- 发布三维服务。
- 发布空间分析服务。
- 前端不再直接消费本地 JS/GeoJSON 作为主 GIS 数据源。

### 第四阶段：Web 端接入 iClient3D

目标：

- 数字园区首页变成 iClient3D 三维场景。
- 传感器、泄漏源、扩散云团、疏散路径作为图层进入三维。
- Web 端形成最强演示闭环。

### 第五阶段：算法结果转 SuperMap 图层

目标：

- 扩散结果转浓度栅格、等值线或三维云团。
- 溯源结果转候选源点、概率圆。
- 疏散结果转路线、阻断区、安全出口。
- YOLO 结果转人员点位或事件点。

### 第六阶段：移动端轻量化

移动端不要先做重。

优先做 H5：

- 告警列表。
- 简化地图。
- 任务确认。
- 现场处置记录。

iMobile 可以作为加分项，但不应该作为第一优先级。

## 11. 诚实边界

答辩和文档中必须继续保留以下边界：

- OSM 是公开众包数据，不是现场测绘。
- 天地图是官方底图引用，不是自采影像。
- 传感器读数当前不是硬件真实采集。
- 三维白模不是倾斜摄影。
- 算法验证有真实数据和失败边界，不能包装成全部通过。
- 移动端如果只是 H5，不要说成完整 iMobile 原生应用。

## 12. 本轮最终结论

当前最务实的一等奖路线：

```text
先修 SuperMap 大屏可演示
  -> 再用 iDesktopX / iServer / iPortal / iClient3D 重塑 GIS 主体
  -> 保留现有扩散、溯源、疏散算法作为创新核心
  -> Web 端先闭环
  -> 移动端后补轻量协同
  -> 最后做 PPT、视频、文档证据链
```

不要从移动端开始，不要推倒重写算法，不要只把 iPortal 当 iframe 外链。
